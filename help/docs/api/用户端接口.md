# 用户端 API

> 核对日期：2026-09-14。调用方是 `frontend/uni-app/src/` 中的 Vue 3/uni-app CLI 用户端，目标平台需单独验证。

## 1. 基础信息

| 项目 | 值 |
|---|---|
| 基础路径 | `/api` |
| v2 路径 | `/api/v2` |
| 调用方 | `frontend/uni-app` |
| 认证头 | `Authori-zation: Bearer <token>` |
| 渠道头 | `Form-type: h5/wechat/routine/app` |
| 语言头 | `Cb-lang` |
| 响应 | `{status,msg,data?}` |

用户端请求封装位于 `frontend/uni-app/src/utils/request.js`，会把接口相对路径拼接为 `{HTTP_REQUEST_URL}/api/{path}`。

## 2. 认证级别

| 级别 | 行为 | 示例 |
|---|---|---|
| 公开 | 不要求 token | 登录、注册、支付回调、版本 |
| 可选登录 | token 有效则注入用户，否则游客 `uid=0` | 首页、商品浏览、商城配置 |
| 强制登录 | token 无效返回认证失败 | 个人信息、购物车、订单、售后 |

路由文件使用嵌套 group；判断接口认证级别时应检查整个 group 的中间件链。

## 3. 登录与注册

### 3.1 统一登录（推荐）

```http
POST /api/auth/login
```

请求：

```json
{
  "channel": "h5",
  "login_type": "password",
  "credentials": {
    "account": "13800000000",
    "password": "REDACTED"
  }
}
```

字段：

| 字段 | 说明 |
|---|---|
| `channel` | 渠道处理器 key，如 `h5`、微信相关渠道 |
| `login_type` | 渠道支持的登录方式，如 password、code/OAuth 类型 |
| `credentials` | 由对应渠道认证器解释的凭证对象 |

成功响应：

```json
{
  "status": 200,
  "msg": "登录成功",
  "data": {
    "token": "...",
    "expires_time": 0,
    "user_info": {}
  }
}
```

部分渠道可能返回 `isbind=true` 和临时 `key`，要求先绑定手机号；扫码登录可能返回轮询状态。

### 3.2 统一注册

```http
POST /api/auth/register
```

当前统一注册控制器主要支持 H5 账号/手机号注册：

```json
{
  "channel": "h5",
  "account": "13800000000",
  "captcha": "REDACTED_CODE",
  "password": "REDACTED",
  "spread": 0
}
```

### 3.3 退出

```http
GET /api/auth/logout
Authori-zation: Bearer <token>
```

会删除 token 缓存并触发用户退出事件。

### 3.4 历史兼容入口

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/login` | H5 账号密码登录，代码已标记推荐迁移统一登录 |
| POST | `/api/login/mobile` | 手机号登录 |
| POST | `/api/register` | 手机号注册 |

- `GET /api/transfer/info?order_id=...&type=1`：当前用户的只读转账详情。
- `POST /api/transfer/info`：收款前查询微信原单并同步到账/失败状态；微信确认过期或取消后自动拒绝并返佣。

POST 请求体为 `{"order_id":"原商户转账单号"}`，单号须为最长 64 字符的字母数字字符串。必须登录，服务端校验提现记录归属。响应 `data.can_receive=true` 才允许用户确认收款，参数使用响应中的原 `mchid`、`wechat_appid` 和 `package_info`；外层 `status=200` 不代表到账，到账需 `data.status=1` 且 `data.state=SUCCESS`。查询超时或结果未知不会返佣。支付与退款排障见 [运维手册](../运维手册.md)，安全边界见 [安全与配置](../安全与配置.md)。

## 14. 支付回调与定时接口

服务接口包括：

- `ANY /api/pay/notify/:type`：支付回调。
- `ANY /api/transfer/notify/:type`：商户转账回调。
- `ANY /api/order_call_back`：寄件回调。

回调必须由服务端验签，不能仅依赖路径保密。

`/api/crontab/*` 存在历史 HTTP 定时任务入口。生产优先使用 `php think timer` 的内部任务注册机制；如保留 HTTP 定时入口，应额外限制来源和权限，避免公网任意触发。

curl 'http://localhost:8011/api/center/order/list?page=1&limit=10' \
  -H 'Authori-zation: Bearer USER_TOKEN' \

## 16. 前端处理约定

uni-app 请求层：

- 顶层 `status=200` resolve；
- `status=401` 跳转/触发登录；
- `status=402` 显示站点提示；
- 其他状态 reject `msg`；
- `noVerify=true` 时由调用方自行解释完整响应；
- `noAuth=true` 跳过前端登录检查，但服务端权限仍生效。

完整接口以 `backend/app/api/route` 及启用模块的 `route/user.php` 为准。
