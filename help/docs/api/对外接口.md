# 对外开放 API

> 核对日期：2026-09-17。写接口可能影响订单、资金和外部服务，不用于无授权的试调用。

## 1. 概述

开放平台模块 `outapi` 为第三方 ERP、OMS、CRM、会员或自动化系统提供商品、分类、订单、售后、优惠券和用户接口。

| 项目 | 值 |
|---|---|
| 模块 key | `outapi` |
| 基础路径 | `/api/outapi` |
| 管理配置 | `/adminapi/setting/system_out_account/*` |
| 认证 | appid/appsecret 换 token，之后按账号接口权限校验 |
| 路由来源 | `backend/modules/service/outapi/route/user.php` |

模块必须安装且启用，否则路由不会加载。

## 2. 账号与权限

管理员在开放平台账号管理中：

1. 创建账号并生成/设置 `appid` 和 `appsecret`。
2. 为账号选择允许调用的接口规则。
3. 设置启用/禁用状态。
4. 可选配置对外推送地址、推送账号和 token 获取地址。

请求通过 token 后，中间件还会调用 `OutInterfaceServices::verifyAuth()` 校验当前路由是否在账号权限内。

## 3. 获取 token

```http
POST /api/outapi/access_token
Content-Type: application/json
```

```json
{
  "appid": "YOUR_APP_ID",
  "appsecret": "YOUR_APP_SECRET"
}
```

成功响应：

```json
{
  "status": 200,
  "msg": "操作成功",
  "data": {
    "access_token": "...",
    "exp_time": 0,
    "auth_info": {}
  }
}
```

`auth_info` 已隐藏 appsecret、IP 和内部状态字段。

## 4. 刷新 token

```http
POST /api/outapi/refresh_token
Content-Type: application/json
```

```json
{
  "access_token": "CURRENT_TOKEN"
}
```

刷新会校验当前 token 和账号状态，删除旧 token 缓存并签发新 token。

## 5. 调用受保护接口

```http
Authori-zation: Bearer <access_token>
```

也兼容标准 `Authorization`。不建议使用 query/body `token` 回退。

```bash
curl 'https://example.com/api/outapi/product/list?page=1&limit=20' \
  -H 'Authori-zation: Bearer OUTAPI_TOKEN'
```

## 6. 商品分类接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/outapi/category/list` | 分类列表 |
| GET | `/api/outapi/category/:id` | 分类详情 |
| POST | `/api/outapi/category` | 新增分类 |
| PUT | `/api/outapi/category/:id` | 修改分类 |
| DELETE | `/api/outapi/category/:id` | 删除分类 |
| PUT | `/api/outapi/category/set_show/:id/:is_show` | 修改显示状态 |

删除分类前应确认子分类、商品关联和软删除策略。第三方系统应保存本系统分类 ID 映射，不用名称作为唯一键。

## 7. 商品接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/outapi/product/list` | 商品列表 |
| GET | `/api/outapi/product/:id` | 商品详情 |
| POST | `/api/outapi/product` | 新增商品 |
| PUT | `/api/outapi/product/:id` | 修改商品 |
| PUT | `/api/outapi/product/set_show/:id/:is_show` | 上下架 |
| PUT | `/api/outapi/product/stock/upload` | 同步商品库存 |

商品是“商品中台 + 产品类型扩展”模型。第三方写商品时需要确认目标产品类型、SKU 字段、分类、物流和专属扩展是否由接口支持；不要默认所有产品类型使用同一字段集。

库存同步属于高风险写操作：

- 按商品/SKU 唯一标识更新；
- 明确传入值是覆盖量还是增量；
- 添加第三方请求流水号；
- 并发时以服务端条件更新和库存日志为准；
- 同步失败后先查询再重试。

## 8. 订单接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/outapi/order/list` | 订单列表 |
| GET | `/api/outapi/order/:order_id` | 订单详情 |
| PUT | `/api/outapi/order/remark/:order_id` | 修改备注 |
| PUT | `/api/outapi/order/receive/:order_id` | 确认收货 |
| GET | `/api/outapi/order/express_list` | 物流公司列表 |
| PUT | `/api/outapi/order/delivery/:order_id` | 整单发货 |
| PUT | `/api/outapi/order/distribution/:order_id` | 修改配送信息 |
| GET | `/api/outapi/order/split_cart_info/:order_id` | 可拆分商品列表 |
| PUT | `/api/outapi/order/split_delivery/:order_id` | 拆单发货 |
| PUT | `/api/outapi/order/invoice/:order_id` | 修改订单发票 |
| PUT | `/api/outapi/order/invoice_status/:order_id` | 修改发票状态 |

调用规则：

- `order_id` 的具体含义以接口响应/Controller 为准，集成时明确是中台订单号还是历史订单号。
- 发货前确认订单已支付、未退款、当前状态允许发货。
- 拆单发货使用接口返回的可拆分商品标识，不从商品当前数据自行推导。
- 重复发货请求必须先查询订单配送结果。
- 发票状态与发票内容变更应有外部发票号或文件凭证。

## 9. 售后/退款接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/outapi/refund/list` | 售后订单列表 |
| GET | `/api/outapi/refund/:after_sale_no` | 售后详情 |
| PUT | `/api/outapi/refund/remark/:after_sale_no` | 修改售后备注 |
| PUT | `/api/outapi/refund/agree/:after_sale_no` | 同意申请 |
| PUT | `/api/outapi/refund/refuse/:after_sale_no` | 拒绝申请 |
| PUT | `/api/outapi/refund/:after_sale_no` | 执行退款 |

退款接口可能触发真实资金操作：

- 单独分配权限；
- 请求前查询售后状态和可退金额；
- 记录第三方流水号；
- 超时后查询退款单和支付渠道，禁止直接重复提交；
- 部分退款需明确商品、运费、优惠和资产分摊；
- 退款成功后检查本地副作用和订单中台状态。

## 11. 用户与等级接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/outapi/user_level/list` | 用户等级列表 |
| GET | `/api/outapi/user/list` | 用户列表 |
| GET | `/api/outapi/user/info/:uid` | 用户详情 |
| POST | `/api/outapi/user` | 新增用户 |
| PUT | `/api/outapi/user/:uid` | 修改用户 |
| PUT | `/api/outapi/user/give_balance/:uid` | 赠送余额 |
| PUT | `/api/outapi/user/give_point/:uid` | 赠送积分 |
| PUT | `/api/outapi/user/change_balance/:uid` | 修改余额 |
| PUT | `/api/outapi/user/change_point/:uid` | 修改积分 |

余额/积分接口：

- “赠送”和“修改”语义不同，接入前确认是增量还是目标值。
- 每次请求带外部流水号和原因。
- 服务端应写对应账单，第三方定期对账。
- 权限与普通用户读取权限分开。
- 设置单次/每日额度和异常告警。

## 13. 对外推送

模块包含 `OutPushJob`，说明对外通知通过队列异步执行。配置推送时注意：

- 推送目标使用 HTTPS。
- 限制内网/本机/云元数据地址，防止 SSRF。
- token 获取和业务推送设置连接、读取和总超时。
- 每次推送记录事件 ID、业务单号、次数和响应摘要。
- 接收方以事件 ID 幂等。
- 重试使用退避和上限，失败进入人工补偿。

## 14. 错误处理

常见错误：

| 现象 | 原因 |
|---|---|
| 404 | 模块未启用、路径/方法错误或 Nginx rewrite 错误 |
| 登录失败 | appid 不存在、appsecret 错误、账号禁用 |
| 登录已过期 | token 缓存失效、JWT 过期或旧 token 已被刷新 |
| 无权限 | 当前账号规则不包含该路由 |
| 参数错误 | 字段缺失、类型/状态不满足业务规则 |

调用方只在明确安全的条件下重试，写操作先查询业务结果。

## 16. 上线联调清单

- 单独创建测试对外账号和最小权限。
- 获取 token、刷新 token、旧 token 失效均符合预期。
- 无 token、用户 token、管理员 token 均不能访问外部受保护接口。
- 未授权路由被拒绝。
- 分类/商品读取与分页字段对齐。
- 商品写入和 SKU/产品类型映射正确。
- 发货/拆单发货重复请求不产生重复配送。
- 售后审核和退款在沙箱完成完整链路。
- 余额/积分变更写入账单并可对账。
- 推送超时、重试和接收方幂等已验证。
- 所有日志不包含 appsecret 和完整 token。
