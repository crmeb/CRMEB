# API 文档总览

> 核对日期：2026-09-14。REST 接口以路由、中间件、控制器和前端封装共同为准；下方是稳定约定与维护索引，不是完整 OpenAPI 定义。

## 1. 接口域

| 接口域 | 基础路径 | 调用方 | 认证 |
|---|---|---|---|
| 管理端 API | `/adminapi` | Vue 管理后台 | 管理员 token + 角色权限 |
| 用户端 API | `/api` | H5、小程序、App | 无认证/可选登录/强制登录 |
| 用户端 v2 | `/api/v2` | 新版用户功能 | 与用户端相同 |
| 中台 API | `/api/center` | 用户端统一商品/订单 | 商品可游客，订单强制登录 |
| 客服工作台 | `/adminapi/kefu` | 客服工作台/游客咨询 | 授权组使用客服 token，游客组免登录 |
| 对外 API | `/api/outapi` | 第三方系统 | 外部账号 token + 路由权限 |
| 独立 MCP | `POST /api/mcp` | AI 客户端 | `mcp_enabled` 总开关 + MCP 账号密钥（`X-Mcp-Key` 或标准 Authorization） |
| AI Agent | `/adminapi/aiagent` | 管理后台 | 管理员 token + 角色权限 |

`/admin` 是管理端页面路径，不是 API 前缀。

模块入口需要对应插件安装并启用。MCP 由独立的 `service_mcp` 插件提供，不属于开放平台对外 API；接入、认证、工具和错误处理见 [MCP 接口](MCP接口.md)。

## 2. 请求协议

### 2.1 Content-Type

普通 JSON 请求：

```http
Content-Type: application/json
```

文件上传使用 `multipart/form-data`。客户端应让请求库生成包含 boundary 的完整 Content-Type，不要手工写死 boundary。

### 2.2 认证头

项目默认认证头：

```http
Authori-zation: Bearer <token>
```

服务端兼容标准头：

```http
Authorization: Bearer <token>
```

还兼容 GET/POST 参数 `token`，但这是历史回退，新集成不应使用，因为 URL 和请求参数更容易被日志记录。

### 2.3 渠道头

用户端通过 `Form-type` 标识来源：

| 值 | 典型来源 |
|---|---|
| `h5` | 普通 H5 浏览器 |
| `wechat` | 微信内 H5 |
| `routine` | 微信小程序 |
| `app` | App |

语言头：

```http
Cb-lang: zh-cn
```

服务端 CORS 配置还允许 `Invalid-zation` 等历史头。新增客户端应只发送实际需要的头。

## 3. 响应结构

以下是普通 REST 响应，MCP 使用 JSON-RPC 协议，AI Agent 流式接口使用事件流，不能统一按 `{status,msg,data}` 解析。

### 3.1 成功

```json
{
  "status": 200,
  "msg": "success",
  "data": {}
}
```

无数据时可能没有 `data` 字段：

```json
{
  "status": 200,
  "msg": "操作成功"
}
```

### 3.2 失败

```json
{
  "status": 400,
  "msg": "参数错误",
  "data": {}
}
```

### 3.3 带业务状态

支付等流程可能使用：

```json
{
  "status": 200,
  "msg": "前往支付",
  "data": {
    "status": "PAY_DEFICIENCY",
    "result": {}
  }
}
```

客户端要同时检查顶层 `status` 和特定业务接口的 `data.status`。

## 4. 状态码语义

项目主要用 JSON 顶层 `status` 表达业务状态，HTTP 状态并不总与业务状态一一对应。

| 业务状态 | 常见含义 |
|---:|---|
| 200 | 成功 |
| 400 | 参数、业务规则或通用失败 |
| 401 | 用户端登录无效/过期 |
| 402 | 站点维护等需要客户端弹窗的状态 |
| 403 | 管理端认证/权限或特殊编辑 token 过期 |

异常处理在 Debug 模式可能返回文件、行号和堆栈；生产必须关闭 Debug。

## 5. 分页

通用请求参数：

| 参数 | 类型 | 默认 | 限制 |
|---|---|---:|---:|
| `page` | int | 1（由业务默认） | >= 1 |
| `limit` | int | 10 | 最大 100 |

典型响应：

```json
{
  "status": 200,
  "msg": "success",
  "data": {
    "list": [],
    "count": 0
  }
}
```

部分历史接口可能返回不同分页结构，接入前以目标 Controller/Service 实现为准。

## 6. 路径参数和可选参数

ThinkPHP 路由示例：

- `:id`：必填路径参数，例如 `/api/center/order/detail/:orderNo`。
- `[:key]`：可选路径参数，例如 `/adminapi/download/[:key]`。
- 路由配置为完全匹配，尾部多余路径通常不会自动兼容。

## 7. 认证模型

### 7.1 管理端

管理端登录后获得 token。受保护接口通常经过：

1. `AdminAuthTokenMiddleware`；
2. `AdminCheckRoleMiddleware`；
3. `AdminLogMiddleware`。

服务端把身份注入请求：`adminId()`、`adminInfo()`。非超级管理员按当前路由规则验证权限。

### 7.2 用户端

用户端三种模式：

- 公开：完全不解析用户。
- 可选登录：token 无效降级游客，`uid()` 为 0。
- 强制登录：认证失败返回业务错误。

查看路由时必须同时检查 group 上的中间件和嵌套 group，不能只看单行路由。

### 7.3 对外账号

第三方使用 appid/appsecret 获取 `type=out` 的独立 token。每次受保护请求还会检查该账号是否有当前路由权限，用户或管理员 token 不能替代。

## 8. 幂等与重试

客户端可以安全重试只读 GET，但写接口是否可重试取决于业务幂等设计。

以下请求不能在超时后无条件重发：

- 下单、支付、退款；
- 余额/积分/佣金变更；
- 库存同步；
- 发货、确认收货；
- 创建优惠券或用户。

第三方集成应提供自己的请求流水号，并在超时后先查询业务结果。支付/退款回调可能重复到达，服务端必须幂等。

## 9. 版本策略

- 大量用户接口直接位于 `/api/...`，属于现有主版本。
- 部分新版接口位于 `/api/v2/...`。
- 模块用户路由由 `/api` 应用动态加载，可自行声明前缀。
- 对外 API 当前没有 URL 版本段，兼容性变更要更谨慎。

建议新接口：

- 保持现有字段只增不删；
- 枚举新增时客户端有未知值兜底；
- 破坏性变更使用明确版本前缀；
- 标记弃用入口、迁移方式和下线时间；
- API 文档与路由变更同提交。

上述是接口兼容性建议，不意味着当前已发布存量版本。首版插件和安装定义仍按 `.crmeb/` 的当前阶段约定维护。

## 11. 调用示例

### 11.1 认证请求

```bash
curl 'http://localhost:8011/api/user' \
  -H 'Authori-zation: Bearer YOUR_TOKEN' \
  -H 'Form-type: h5' \
  -H 'Cb-lang: zh-cn'
```

### 11.2 分页请求

```bash
curl 'http://localhost:8011/api/center/product/list?page=1&limit=10'
```

示例中的 token、账号和域名均需替换为当前环境值，不要把真实令牌写进脚本仓库或工单。

## 12. 接口变更检查

- HTTP 方法和路径是否与前端封装一致。
- 请求字段必填、类型、范围和默认值是否明确。
- 响应 `data` 的对象/数组类型是否保持稳定。
- 权限、资源归属和数据范围是否验证。
- 金额、库存和状态写操作是否幂等。
- 列表是否受最大分页限制。
- 错误信息是否泄露内部结构或个人信息。
- 模块禁用时是否正确停止加载路由。
- OpenAPI/接口管理数据和本文档是否需要同步。
