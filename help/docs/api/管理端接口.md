# 管理端 API

> 核对日期：2026-09-14。管理端使用 Vue 3、Element Plus、Pinia 和 Vite；页面路径与 API 路径独立。

## 1. 基础信息

| 项目 | 值 |
|---|---|
| 基础路径 | `/adminapi` |
| 调用方 | `frontend/admin` |
| 默认开发代理 | `http://localhost:8011` |
| 认证头 | `Authori-zation: Bearer <token>` |
| 响应 | `{status,msg,data?}` |
| 分页 | `page`、`limit`，最大 100 |

管理端页面本身位于 `/admin`，API 位于 `/adminapi`。

## 2. 登录

### 2.1 登录页信息

```http
GET /adminapi/login/info
```

返回登录页 Logo、轮播或相关配置。

### 2.2 管理员登录

```http
POST /adminapi/login
Content-Type: application/json
```

请求字段：

| 字段 | 必填 | 说明 |
|---|:---:|---|
| `account` | 是 | 管理员账号 |
| `pwd` | 是 | 密码，长度 6-32 |
| `key` | 否 | 历史验证码/登录关联 key |
| `captchaVerification` | 条件 | 二次滑块验证码结果 |
| `captchaType` | 条件 | 验证码类型 |

示例：

```json
{
  "account": "admin",
  "pwd": "REDACTED",
  "captchaVerification": "",
  "captchaType": ""
}
```

响应 `data` 中包含管理端登录结果和 token 信息，前端将 token 写入 Cookie。

### 2.3 验证码

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/adminapi/captcha_pro` | 获取验证码 |
| GET | `/adminapi/ajcaptcha` | 获取滑块/行为验证码 |
| POST | `/adminapi/ajcheck` | 一次验证 |

## 3. 权限链

绝大多数业务路由使用：

```text
AllowOriginMiddleware
  -> AdminAuthTokenMiddleware
  -> AdminCheckRoleMiddleware
  -> AdminLogMiddleware
```

管理端接口开发注意：

- 前端菜单隐藏不能替代后端权限校验。
- 路由 `real_name` 和菜单 API 是权限管理基础数据。
- 非超级管理员由 `SystemRoleServices::verifyAuth()` 校验当前路由。
- 写操作由管理日志中间件记录。

务必检查具体路由文件：例如当前 `center.php` 只显式挂载跨域与管理员认证中间件，不可据本文推断每条路由已经具备完整角色校验和操作审计。新增敏感写接口仍需按 [安全与配置](../安全与配置.md) 验证权限链。

## 7. 订单中台与售后

统一订单入口位于 `center.php`/`order.php`：

- 订单列表、详情和各订单类型扩展。
- 订单备注、状态、发货、拆单、配送和收货。
- 订单打印、导出和发票。
- 售后列表、详情、审核、退货和退款。

管理端订单操作必须以订单当前状态和适配器返回的可操作按钮为准，不能仅依赖前端显示状态。

## 8. 用户与会员

`user.php` 覆盖：

- 用户列表、创建、详情和编辑；
- 分组、标签、等级；
- 余额、积分、佣金赠送/调整及账单；
- 会员类型、权益、会员卡批次和会员订单；
- 用户注销、地址、发票和行为信息。

资产变更接口属于高风险权限，调用方应提供操作原因；服务端应同时写资产账单和管理员日志。

## 9. 模块路由

管理应用启动时自动扫描：

```text
backend/modules/*/route/admin.php
backend/modules/*/*/route/admin.php
```

主要模块管理路由包括：

- `channel/h5`、`channel/wechat_mini`：渠道；
- `product_normal`、`product_virtual`：产品类型；
- `user_signin`：营销；
- `service_mcp`：MCP 服务；
- `aiagent`：AI 对话、自动化任务、MCP 服务连接、Skill 与附属资料管理。

模块未启用时，对应路由不会加载。

AI Agent 的 `/adminapi/aiagent/chat_stream` 和 `confirm_stream` 使用流式响应，代理需要避免缓冲和超时截断；具体事件结构以控制器与前端消费实现为准。Skill key 允许连字符，附属文件名通过查询参数 `file` 传递，不拼入路径变量。

## 10. 模块/插件管理

管理端存在模块和插件生命周期接口，提供：

- 清单列表、详情和依赖检查；
- 安装、卸载；
- 启用、禁用；
- 模块菜单和资源刷新。

安装/卸载会执行 DDL 和数据清理，不能作为普通可重试 HTTP 请求处理。超时后先查询模块状态和数据库结构。

## 11. 驱动管理

`driver.php` 是管理端路由数量最大的分域之一，包含：

- 驱动列表与可用清单；
- 支付渠道和终端平台配置；
- 上传驱动与存储空间；
- 短信、邮件、机器人；
- 物流、电子面单、发票；
- 打印渠道与打印机；
- 商品采集。

驱动配置响应必须隐藏 secret、私钥和完整证书；保存时使用后端校验，不能信任前端掩码值。

默认安装清单见 [模块说明](../模块与驱动.md)。安装日志、驱动字典、业务启用开关与服务商配置是不同层次；同名 key 在不同类别中可复用，生命周期管理使用规范化复合身份。

## 13. 调试与排错

- 404：确认 `/adminapi` 前缀、HTTP 方法、模块状态和 Nginx rewrite。
- 400：读取 JSON `msg`，检查验证器场景和业务状态。
- 403：检查 token、管理员状态、角色路由权限和文件编辑 token。
- 菜单有页面无权限：检查菜单 API、路由 `real_name` 和角色授权。
- 超时：检查导出、第三方驱动、慢 SQL 和队列是否错误地同步执行。

完整接口以 `backend/app/adminapi/route` 与已启用模块的 `route/admin.php` 为准。
