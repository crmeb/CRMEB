# 部署指南

> 核对日期：2026-09-17。本地开发默认使用宿主机环境；根 Compose 是可选部署方式。生产需单独完成凭据、网络、持久化和守护配置。

## 1. 部署组成

完整运行环境至少包含：

- Nginx 或等价反向代理；
- PHP-FPM 8.2-8.4；
- MySQL 8；
- Redis；
- Redis 队列消费者；
- Timer 定时进程；
- Workerman WebSocket 进程；
- 管理端和用户端构建产物；
- 上传文件存储或对象存储；
- TLS 证书、支付证书及第三方服务配置。

只启动 Nginx、PHP、MySQL 和 Redis 会使页面/API 可访问，但订单异步任务、自动收货、消息通知和客服实时通信可能不工作。

## 2. Docker 部署（可选）

本节仅适用于用户明确选择 Docker 或现有目标实例已运行在容器中的场景。宿主机本地开发见 [开发指南](开发指南.md)。

### 2.1 本地快速启动

```bash
./run.sh start
```

首次且允许清空数据时：

```bash
./run.sh install
```

`install` 会删除已有容器数据目录和运行数据，生产环境不得直接使用该命令覆盖现有实例。

### 2.2 Compose 服务

根目录 `docker-compose.yml` 提供 MySQL、Redis、PHP-FPM、Nginx、Timer、Queue 和 Workerman 七个服务。默认配置适合本地开发，生产使用前至少调整：

- 删除 MySQL/Redis 公网端口映射或限制监听地址；
- 替换所有默认密码；
- 避免固定容器 IP 与现有网络冲突；
- 使用受控镜像版本和镜像仓库；
- 为数据库和上传资源配置可靠持久卷；
- 为 PHP/Nginx 设置资源限制和健康检查；
- 校验现有队列、Timer、Workerman 独立服务的健康、重启策略和业务开关；
- 配置日志轮转与集中采集。

### 2.3 常用命令

```bash
./run.sh ps
./run.sh logs
./run.sh restart
./run.sh stop
```

`run.sh delete` 会清理数据，只有确认环境可销毁时才能使用。

## 3. 手动部署

### 3.1 准备代码与依赖

```bash
cd backend
composer install --no-dev --prefer-dist --optimize-autoloader
composer check-platform-reqs --no-dev
```

PHP-FPM 和 CLI 均需使用 PHP 8.2～8.4，且加载 Composer 要求的扩展（包括 `fileinfo`）。
队列进程依赖的 `symfony/process` 已限定为 6.4 LTS，并锁定到兼容 PHP 8.4 的版本；发布时同步
`composer.json`、`composer.lock` 和依赖目录，不能只更新业务代码或跳过平台检查。
专项回归入口见 [开发指南](开发指南.md)。构建前先核对脚本是否存在，不把历史兼容性脚本当作当前验收入口。

管理端：

```bash
cd ../frontend/admin
npm ci
npm run build:all
```

用户端通过 uni-app CLI 按目标平台构建（从管理端目录切换）：

```bash
cd ../uni-app
npm ci
npm run build:h5
npm run build:mp-weixin
```

H5 产物位于 `frontend/uni-app/dist/build/h5`，部署到后端约定的用户端静态入口；小程序/App 走各平台发布流程，API 域名在构建前通过 `UNI_APP_API_URL` 配置。

### 3.2 Web 根目录

Nginx `root` 必须指向：

```text
{project}/backend/public
```

不能指向仓库根目录或 `backend`，否则可能暴露 `.env`、源码、Composer 文件和运行配置。

### 3.3 URL 重写

非静态资源请求需要重写至 `index.php`。仓库 Nginx 示例的核心行为是：

```nginx
location / {
    if (!-e $request_filename) {
        rewrite ^(.*)$ /index.php?s=$1 last;
    }
}
```

生产可使用等价、可维护的 `try_files` 规则，但必须验证 ThinkPHP 多应用、管理端 history 路由和用户端 fallback。

### 3.4 PHP-FPM

- PHP 版本满足 Composer 约束。
- 安装 JSON、cURL、BCMath、Mbstring、Zip、SimpleXML 等扩展。
- 设置合理的 `memory_limit`、`upload_max_filesize`、`post_max_size` 和执行超时。
- `backend/runtime`、上传目录和需要生成的静态目录对 PHP 用户可写。
- 关闭生产 `display_errors`，将错误写入日志。

## 4. 数据库初始化与升级

### 4.1 新安装

优先通过项目安装向导或既定安装流程执行，基础表来自：

- `backend/public/install/crmeb_table.sql`；
- `backend/public/install/crmeb_data.sql`；
- 必需模块、默认模块和默认驱动 Installer，具体清单见 [模块说明](模块与驱动.md)。

安装后立即：

1. 修改默认管理员密码。
2. 验证模块安装日志。
3. 执行插件清单和注册中心检查。
4. 检查队列、定时器与 WebSocket。

### 4.2 首版变更与历史迁移边界

当前处于首版开发阶段。核心结构和数据直接更新安装 SQL，插件自有结构、菜单、种子直接更新 Installer；插件清单和 Installer 版本统一为 `1.0.0`，不为未发布功能新增旧站点升级链。

新装后核对 `eb_pay_record`、`eb_refund_order`、`eb_refund_effect`、模块日志、驱动字典及任务注册，不能依赖某个历史文件名判断结构完整。

未来明确维护存量站点时，先备份数据库、上传资源和部署配置，再按目标版本逐项评估表前缀、字段、数据回填、菜单资源归属与支付合同兼容性；不能只替换代码，也不能未经评估批量执行历史 SQL。

## 5. 静态资源部署

### 5.1 管理端

管理端 Vite `base` 是 `/admin`，生产资源需最终出现在后端 `public/admin` 可访问位置。默认输出到 `frontend/admin/dist`，发布流程应显式同步产物，不能假设构建自动写入 PHP public 目录。

需要同时发布：

- 主管理端构建产物；
- `static/extensions` 下的插件 UMD 包；
- 正确的 `index.html` 和资源版本。

### 5.2 用户端 H5

用户端全局兜底会返回部署后的 `public/index.html`（相对 `backend/`）。该文件是 H5 构建发布到后端后的运行时入口，不要求存在于源码仓库；发布时确认：

- 入口文件和所有静态 chunk 存在；
- history 路由 fallback 正确；
- API 域名和 `/api` 前缀正确；
- 静态资源缓存不导致入口引用旧 chunk；
- `mobile.html` 中的跳转站点地址可用。

### 5.3 缓存策略

- 带内容哈希的 JS/CSS 可长缓存。
- `index.html`、插件入口清单和动态配置不应长时间强缓存。
- 发布后不要只删除旧 chunk；先确保新入口生效，再清理无人引用的资源。

## 6. WebSocket

统一入口：

```nginx
location /ws {
    proxy_pass http://crmeb_workerman:40001;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_read_timeout 3600s;
    proxy_send_timeout 3600s;
}
```

生产 HTTPS 站点应由 Nginx 提供 WSS，后端 Workerman 保持普通 WS。不要将内部 Channel 端口 `40003` 暴露公网。

## 7. 后台进程守护

### 7.1 队列

根 Compose 已运行独立 `queue` 服务，由 `docker/queue-worker.sh`（以只读方式挂载为容器内 `/repo/docker/queue-worker.sh`）启动消费者并更新 `runtime/.queue_heartbeat`。使用该编排时不要再在 PHP-FPM 容器或宿主机重复启动；先检查队列容器、心跳和业务开关。下方命令与守护建议用于非 Compose 部署。

启动消费者不等于业务已启用异步队列。必须同时在管理后台开启消息队列配置（`queue_open=1`），并在 `backend/.env` 设置：

```ini
[CACHE]
DRIVER = redis
```

两项缺一时，基础任务类会走同步执行。订单创建监听器会跳过延迟提醒和取消任务并记录警告，取消任务本身也会核对创建时间，避免新订单被提前取消。正常自动取消仍需要正确配置异步队列；取消时长 `order_cancel_time` 单位为小时，必须大于 0，0 或负数不投递取消任务。

宝塔守护进程工作目录指向项目 `backend`，使用已安装且扩展齐全的 PHP 8.2～8.4 绝对路径（例如 `/www/server/php/82/bin/php`）。保存配置和部署代码后重启队列进程并重载 PHP-FPM。消费者与网站必须使用同一份环境配置和 Redis 数据库；默认队列名为 `CRMEB`，配置了 `queue.queue_name` 时会追加该后缀，显式指定队列名需与之一致。

验收时创建测试订单，确认刚下单保持待支付，配置时长到期后才取消；已支付订单不应取消。检查运行日志是否出现“跳过订单延迟任务”或“订单尚未到期且异步队列未启用”。此保护不会恢复此前已经取消的订单。

```bash
php think queue:listen --queue
```

建议 Supervisor/systemd 配置：

- 自动启动和异常重启；
- 工作目录指向 `backend`；
- 启动命令使用 PHP 8.2～8.4 可执行文件的绝对路径，避免终端默认 PHP 与 PHP-FPM 版本不一致；
- 使用与 PHP-FPM 相同代码和环境变量；
- 分环境队列前缀；
- 标准输出和错误日志轮转；
- 发布时优雅停止，更新代码后重启。

### 7.2 Timer

```bash
php think timer start --d
```

Timer 自身可守护，但仍建议由主机进程管理或容器编排监督，并监控 PID 与最近任务执行时间。

根 Compose 以 `php think timer start` 前台运行并由容器重启策略托管，不在容器内叠加 `--d` 或另一套守护进程。

### 7.3 Workerman

```bash
php think workerman start --d
```

发布模块事件或 WebSocket 处理器后重启 Workerman。多实例部署时要规划连接路由、在线状态和内部 Channel 通信，不能简单启动多个互不共享状态的网关。

根 Compose 以 `php think workerman start` 前台运行；Nginx `/ws` 转发到独立的 `crmeb_workerman`，不是 PHP-FPM 服务。

## 8. 生产环境配置

必须调整：

- `APP_DEBUG=false`；
- 数据库 `debug=false`；
- 缓存驱动 Redis；
- 唯一的缓存和队列前缀；
- 强随机 `APP_KEY`、数据库密码、Redis 密码；
- 文件管理开发密码；
- 上传白名单、大小和对象存储权限；
- CORS 允许来源；
- 支付回调公网 URL 和证书；
- 小程序/公众号/App 的生产应用配置；
- 日志级别、保留时间和脱敏；
- 备份、监控和告警。

## 9. 滚动发布建议

1. 明确发布结构、Installer 与配置基线并完成备份。
2. 构建后端 Composer 依赖和前端静态产物。
3. 在隔离环境验证首版新装、插件检查和关键流程；若已明确维护旧站点，另行验证选定迁移。
4. 对大表 DDL 单独安排维护窗口。
5. 暂停或排空会受影响的队列任务。
6. 发布静态资源和新代码。
7. 首版按安装定义验证结构；旧站点仅执行已经评审与演练的数据库/插件增量变更。
8. 重载 PHP-FPM，重启队列、Timer、Workerman。
9. 检查健康、日志、队列积压、WebSocket 与第三方回调。
10. 观察订单、支付、退款、库存和通知指标。

由于数据库 DDL 不一定可事务回滚，回滚方案必须包含向前修复 SQL，而不能只依赖代码版本回退。

## 10. 上线验收

- 管理端登录、菜单和至少一个非超级管理员权限正常。
- 用户端首页、商品详情、登录、下单和支付正常。
- 支付回调和退款测试环境回调正常。
- 上传、对象存储域名和图片处理正常。
- Redis、队列消费、失败队列和锁正常。
- Timer 最近执行时间正常。
- `/ws` 能建立连接并收到测试通知。
- 已启用模块路由可用，禁用模块不可访问。
- 对外 API 认证、权限拒绝和一条只读接口正常。
- 日志无密钥/完整个人数据泄露。
- 备份文件可读取，并记录恢复步骤和负责人。
