# 模块与驱动说明

> 核对日期：2026-09-24。以下数量与默认安装标记来自仓库 `plugin.json`，不是当前数据库的启用状态。

## 1. 扩展体系概览

当前代码库包含两套扩展机制：

| 类型 | 目录 | 本次检查数量 | 典型内容 |
|---|---|---:|---|
| 业务模块 | `backend/modules/` | 7 个清单 | 路由、控制器、服务、表、菜单、事件、前端页面 |
| 第三方驱动 | `backend/driver/` | 15 个清单 | 同一能力下的供应商实现与配置 |

业务模块改变“系统能做什么”，驱动改变“同一能力由哪个供应商完成”。例如“用户充值”是业务模块，“微信支付 V3”是支付驱动。

## 2. 模块状态模型

一个模块可能处于以下状态：

| 状态 | 目录存在 | 安装日志 `status` | `enabled` | 运行时行为 |
|---|:---:|:---:|:---:|---|
| 仅有代码 | 是 | 无/0 | 任意 | 通常不应加载；旧库无状态表时存在兼容放行 |
| 已安装未启用 | 是 | 1 | 0 | 保留表和数据，不加载模块处理器和路由 |
| 已安装已启用 | 是 | 1 | 1 | 加载 `App.php`、事件、处理器和场景路由 |
| 已卸载 | 可存在 | 0 | 0 | Installer 可能已删除模块表和菜单 |

运行时判断依据是 `eb_module_install_log`。目录扫描用于发现清单，不能代替安装状态。

### 3.4 产品类型

| key | 名称 | 必需 | 产品类型 | 履约 | 物流 | 售后概览 |
|---|---|:---:|---|---|:---:|---|
| `product_normal` | 实物商品 | 是 | `normal` | 发货/配送/自提 | 是 | 退款、退货退款、换货、维修 |
| `product_virtual` | 网盘产品 | 否 | `virtual` | 自动发放资源 | 否 | 以退款为主，受时限约束 |
| `product_cardkey` | 卡密商品 | 否 | `cardkey` | 自动派发卡密 | 否 | 以退款为主，受时限约束 |

产品类型模块通过三类注册完成运行时接入：

1. `ProductTypeRegistry`：商品保存、SKU、库存、详情和履约。
2. `OrderTypeRegistry`：订单来源到统一订单状态/按钮的适配。
3. `AfterSaleRuleRegistry`：按产品类型声明售后规则。

#### 实物商品 `product_normal`

- 基础商品类型，清单标记 `required=true`。
- 支持通用商品、SKU、物流、自提、订单和售后。
- 可与普通、秒杀、拼团、砍价、积分等交易模式协作。
- 包含未支付取消和自动收货定时任务。

#### 网盘商品 `product_virtual`

- 保存资源链接、提取码等扩展数据。
- 支付后通过履约管线自动发放。
- 不需要物流，应限制可售后范围和时限。
- 模块内包含管理端扩展页面构建产物/源码映射。

#### 卡密商品 `product_cardkey`

- 管理卡密库存并在支付后分配。
- 履约操作必须保证并发下单时卡密唯一、重复回调不重复派发。
- 退款时需明确已查看/已使用卡密的业务处理规则。

### 3.6 服务模块

| key | 名称 | 目录 | 主要能力 |
|---|---|---|---|
| `kefu` | 在线客服 | `modules/service/kefu` | 客服账号、会话、话术、自动回复、反馈、实时通信 |
| `outapi` | 开放平台对外接口 | `modules/service/outapi` | 第三方账号、令牌、权限、业务 API 和推送 |
| `service_mcp` | MCP 服务 | `modules/service/mcp` | 独立 `/api/mcp` 工具入口、服务开关、密钥认证与事件扩展 |
| `aiagent` | AI Agent | `modules/aiagent` | 后台会话、流式对话、自动化任务、MCP 连接与 Skill 管理 |

客服模块提供 `route/admin.php`、`route/user.php` 两类场景路由。工作台与游客组统一挂在 `/adminapi/kefu/`，客服 token 独立于管理员 token；实时服务通过统一 WebSocket 网关注册。

独立 MCP 使用 `mcp_appkey`，不复用开放平台的 `appid/appsecret`；接入和工具说明见 [MCP 接口](api/MCP接口.md)。AI Agent 的模型与工具配置均需单独验收权限和外部调用。

`aiagent` 提供后台 AI 对话工作台、模型/MCP/Skill 运行配置与无人值守自动化任务，依赖 `service_mcp` 的内置业务工具（软依赖）；功能详述、数据表、接口与权限见 [AI Agent 模块](AI%20Agent%20模块.md)。

## 5. 模块自动发现

### 5.1 清单发现

`PluginManifestRepository` 和 `ExtensionRegistry` 扫描模块与驱动的 `plugin.json`，获取：

- `key`、`name`、`description`、`version`；
- `type`、`path`、是否必需；
- CRMEB/PHP 版本要求；
- 可选命令和依赖关系。

清单用于后台展示和一致性检查，不直接代表模块代码已运行。

### 5.2 运行时注册

`ModuleRegistry` 支持扫描一、二、三级模块目录中的 `App.php`：

- `register()` 向注册中心注册处理器或容器绑定；
- `boot()` 加载模块事件、售后规则或其他启动逻辑；
- 有清单的模块先检查安装启用状态；
- 父级骨架目录没有清单时可直接加载公共注册逻辑。

### 5.3 路由发现

`ModuleRouteLoader` 按场景加载：

```text
modules/*/route/{scene}.php
modules/*/*/route/{scene}.php
```

主要场景为 `admin` 和 `user`。客服工作台组由模块 `admin.php` 加载，不再使用独立 `kefu.php` 场景。禁用模块的路由不会被加载。

### 5.4 命令发现

插件可在清单中声明后端命令，`PluginCommandDiscovery` 与核心命令合并到 ThinkPHP Console。

## 6. Installer 设计

业务模块 Installer 通常继承 `crmeb\module\BaseModuleInstaller`；驱动使用统一的清单安装器。业务模块至少实现：

- `getKey()`、`getName()`、`getVersion()`、`getType()`；
- `runMigrate()`：幂等建表/补结构；
- `rollbackMigrate()`：卸载时的数据表策略；
- `getMenuConfig()`：后台菜单与接口权限；
- 可选 `seed()`、`cleanData()`、`checkRequirements()`。

### 6.1 安装

1. 检查依赖和环境。
2. 在事务外执行 DDL。
3. 事务内写入菜单、配置、种子、共享资源归属和安装日志。
4. 清理模块状态缓存。

### 6.2 禁用/启用

- 禁用：隐藏菜单、从模块显示配置移除、停止注册路由/事件/处理器，保留数据。
- 启用：恢复菜单和显示配置，恢复运行时加载。
- 长驻进程需要重启才能完全加载最新模块状态。

### 6.3 卸载

- 清理模块业务数据和菜单。
- 只删除明确属于本插件的共享资源。
- 执行 `rollbackMigrate()`，可能删除模块表。
- 写入卸载状态。

卸载前必须查看具体模块实现；不同插件的数据保留策略可能不同。

## 7. 新增模块规范

### 7.1 目录与命名

```text
modules/{domain}/{name}/
├── plugin.json
├── App.php
├── Installer.php
├── event.php
├── controller/admin/
├── controller/user/v1/
├── route/admin.php
├── route/user.php
├── service/
├── dao/
├── model/
├── validate/
├── listener/
├── jobs/
├── crontab/
└── handler/
```

- 队列目录统一使用复数 `jobs/`。
- 服务类以 `Services` 结尾，DAO 以 `Dao` 结尾。
- 模块 key 应稳定且唯一，安装后不要随意修改。
- 数据表通过 `$this->table('name')` 适配前缀，不硬编码 `eb_`。

### 7.2 必做检查

```bash
cd backend
php think plugin:manifest-check
php think plugin:required-check
php think event:check
php think registry:check
php think channel:menu-check
```

有数据库连接要求的命令应在已安装的测试数据库上执行。

### 7.3 验收矩阵

新增模块至少验证：

- 全新安装、重复安装、禁用、重新启用和卸载；
- 清单依赖缺失、版本不满足和模块未启用访问；
- 菜单幂等、权限分配和非超级管理员访问；
- 路由是否只在目标场景加载；
- 队列重试、事件重复触发和定时任务重复执行；
- 数据表使用自定义前缀时是否正常；
- 长驻队列/定时器/Workerman 重启后的模块加载；
- 管理端页面资源构建、部署和缓存更新。

## 8. 新增驱动规范

1. 放入正确类别 `driver/{category}/{provider}`。
2. 实现该类别公共接口，不把业务订单状态机写进供应商驱动。
3. 提供 `plugin.json`，使用类别与 key 组合后的稳定身份。
4. 敏感配置只保存引用或加密数据，不写入清单和源码。
5. 错误统一转换为业务可识别异常，并保留原供应商请求标识用于排障。
6. 处理超时、重试、签名、证书过期、回调重放和供应商限流。
7. 提供沙箱/测试能力时与生产配置明确隔离。

## 9. 维护注意事项

- 模块之间禁止直接引用具体类；需要协作时先定义稳定契约或事件。
- 模块清单、Installer 的 key/type/path 必须一致。
- 模块菜单 API 路径必须与实际路由和前端路径一致。
- 共享表增加插件字段时应标记资源归属，卸载时不能误删其他模块数据。
- 当前处于首版开发阶段，清单和 Installer 版本统一为 `1.0.0`；核心变更更新安装 SQL，插件自有变更更新 Installer，不新增旧版本升级链。
