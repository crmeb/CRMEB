# 项目功能文档

> 核对日期：2026-09-14。能力说明以当前源码为准；实际菜单、页面与服务可用性取决于安装、权限和配置。

## 1. 文档说明

本文件按用户角色和业务域描述系统功能。功能状态分为三层：

- 核心功能：代码位于 `backend/app`，一般随系统提供。
- 模块功能：代码位于 `backend/modules`，需要安装并启用对应模块。
- 驱动能力：代码位于 `backend/driver`，还需要配置对应服务商账号与参数。

目录中存在源码只表示系统具备该能力，不代表当前数据库已经安装、后台已经开启或第三方账号已经可用。

## 2. 管理端功能总览

### 2.1 工作台与经营概览

- 首页经营数据汇总。
- 订单趋势、用户趋势和交易额排行。
- 商品、订单、用户、资金等统计看板。
- 待处理消息与通知提醒。
- 后台菜单搜索与快捷导航。
- 服务器与系统信息查看。

### 2.2 商品管理

核心商品能力：

- 商品中台列表、创建、编辑、删除、上下架与缓存数据处理。
- 商品分类及分类层级维护。
- 多规格 SKU、属性模板、属性值和库存管理。
- 商品详情、参数、标签、保障服务和关联优惠券。
- 商品图片、视频、富文本详情与附件选择。
- 商品评价列表、回复、虚拟评价和删除。
- 商品采集、导入、导出与批量处理。
- 商品访问、销量和转化统计。

产品类型模块：

| 类型 | 管理能力 | 用户履约 |
|---|---|---|
| 实物商品 | 通用商品与 SKU、物流/配送配置 | 物流、同城配送或门店自提 |
| 网盘商品 | 资源链接、提取信息、虚拟 SKU | 支付后自动发放数字资源 |
| 卡密商品 | 卡密库存导入、批次/库存维护 | 支付后派发卡号密码 |

### 2.3 订单管理

- 订单中台统一列表和详情。
- 按订单号、用户、状态、来源、支付和时间筛选。
- 订单备注、改价、取消、删除和打印。
- 发货、配送信息修改和物流查询。
- 用户确认收货与后台确认收货。
- 订单商品快照、状态日志和操作记录。
- 不同 `source_type` 的订单状态、按钮和详情扩展。
- 线下收银/其他订单处理。
- 订单发票申请、开票状态与电子发票下载。
- 订单导出和配送单打印。

### 2.4 售后与退款

- 售后单列表、详情、筛选和时间线。
- 仅退款、退货退款、换货、维修等类型按产品规则开放。
- 商家同意、拒绝、要求退货、收货确认和结果处理。
- 用户退货物流信息管理。
- 统一退款单创建、提交、状态查询与失败处理。
- 原路退款或相应支付驱动退款。
- 退款后的库存、优惠、积分、佣金等副作用幂等处理。
- 售后与订单中台状态联动。

### 2.5 用户与客户管理

- 用户列表、详情、创建、编辑和状态管理。
- 用户分组、标签、等级及批量设置。
- 余额、积分、经验、佣金等资产调整与记录。
- 用户地址、发票、收藏、浏览、搜索与访问记录。
- 用户注销申请和注销结果管理。
- 会员信息、会员类型、权益、会员卡批次与卡片管理。
- 用户推广关系和分销身份管理。

### 2.6 会员体系

- 会员类型/套餐配置。
- 会员权益配置。
- 会员订单、状态记录和线下开通。
- 会员卡批次生成、卡状态和激活。
- 会员协议维护。
- 用户会员状态、有效期及权益展示。

会员订单使用独立的 `eb_member_order` 体系，不等同于商品交易模式中的普通商品订单。

### 2.7 优惠券与营销

优惠券：

- 优惠券模板创建、编辑、状态和删除。
- 领取活动与前台展示。
- 指定商品/分类适用范围。
- 用户领取、后台发放和使用记录。
- 下单可用券计算和优惠分摊。

可安装营销/交易活动：

| 功能 | 主要能力 |
|---|---|
| 秒杀 | 秒杀时段、活动、商品、SKU 库存、限购、参与记录与订单 |
| 拼团 | 拼团商品、拼团价、人数、成团时限、团列表和到期处理 |
| 砍价 | 砍价商品、活动时间、底价、用户发起、好友助力与统计 |
| 积分商城 | 积分商品、积分/现金组合价、兑换限制、独立积分订单 |
| 签到 | 连续/累计签到规则、奖励、记录和提醒 |
| 抽奖 | 九宫格、大转盘、翻牌等活动、奖品与中奖记录 |
| 新人礼 | 注册后赠送余额、积分或优惠券 |
| 渠道码 | 公众号渠道二维码、分类、扫码记录与统计 |
| 用户充值 | 充值配置、充值订单/记录、充值退款 |

### 2.8 分销与代理

分销代理模块提供：

- 分销员申请、审核、状态与资料管理。
- 分销等级、升级任务和任务记录。
- 用户推广关系、绑定/解绑及关系日志。
- 分销订单佣金快照。
- 佣金计算、冻结、解冻、账单与提现。
- 管理员数据范围和代理业务权限。
- 事业部、代理商、申请和统计相关能力。
- 用户端推广码、推广海报、团队、订单和佣金排行。

佣金信息在订单发生时固化，历史订单不应依赖用户当前推广关系重新计算。

### 2.9 页面装修与内容

- 商城 DIY 页面创建、编辑、复制、删除和发布。
- 主题、主题组件、主题下载与一键换色。
- 底部导航、页面链接和链接分类。
- 开屏广告、首页组件和移动端配置。

### 2.10 门店、配送与物流

- 门店列表、位置、营业信息和自提配置。
- 店员/核销员绑定与权限校验。
- 配送人员管理。
- 运费模板、指定包邮、不配送区域和区域运费。
- 快递公司与物流查询。

### 2.11 财务

- 资金流水和用户账单。

- 用户提现申请、审核和结果处理。
- 分销佣金、冻结佣金与代理提现。

### 2.16 开放平台

- 创建第三方应用账号和 `appid/appsecret`。
- 配置账号可调用的接口权限。
- 获取与刷新访问令牌。
- 商品分类和商品同步。
- 订单查询、备注、发货、拆单和收货。
- 售后查询、审核和退款。
- 优惠券管理。
- 用户、等级、余额和积分操作。
- 对外推送配置和异步推送任务。

### 2.17 AI Agent 与独立 MCP 服务

- `aiagent`：后台 AI 对话、流式响应、会话标题与置顶、自动化任务和运行记录。
- AI 模型、MCP 服务连接、工具同步与 Skill 文件由后台配置；模型凭据不放前端。
- `service_mcp`：通过 `/api/mcp` 向 AI 客户端开放工具，受 `mcp_enabled` 总开关控制（安装默认开启），使用独立账号密钥认证。
- MCP 服务由独立插件提供，不属于开放平台对外 API。
- AI 对话、工具执行和任务调度都可能产生外部调用或数据写入，需单独验收权限、确认流程、限流与审计。

`aiagent` 的完整功能、接口、数据表与已知限制见 [AI Agent 模块](AI%20Agent%20模块.md)。

默认安装哪些能力见 [模块说明](模块与驱动.md)；默认安装不表示模型、微信、存储或机器人凭据已经配置。

## 4. 核心业务流程

### 4.1 新用户注册

1. 客户端根据渠道选择手机号、微信、小程序、App 或统一认证入口。
2. 服务端完成验证码/OAuth 凭证验证。
3. 创建或关联 `eb_user` 及渠道身份。
4. 触发 `UserRegister` 事件。
5. 新人礼模块若启用，可发放余额、积分或优惠券。
6. 返回 token，客户端保存并在后续请求头携带。

### 4.2 普通商品下单

1. 用户浏览商品，选择 SKU、数量和履约方式。
2. 购物车/结算接口校验商品、库存、状态、产品类型与交易模式。
3. 计算活动价、会员价、优惠券、积分、权益和运费。
4. 用户确认地址、自提点、发票和支付方式。
5. 服务端在事务内创建具体订单、商品快照、日志并同步订单中台。
6. 用户发起支付；支付回调校验签名并幂等更新订单。
7. 触发支付成功事件，执行库存确认、通知、分销快照和产品履约。
8. 实物进入发货/自提，虚拟/卡密自动履约。

### 4.3 发货与收货

1. 管理员在订单中台整单发货（系统不支持拆单/分批发货）。
2. 选择快递/配送方式并写入单号和商品明细。
3. 可调用电子面单和打印驱动。
4. 通知用户并记录订单日志。
5. 用户确认收货，或由定时任务按规则自动收货。
6. 完成订单后触发评价、佣金解冻等后续流程。

### 4.4 售后退款

1. 用户端读取订单可用售后类型和动态表单。
2. 用户提交申请，服务端创建售后单和商品明细。
3. 商家审核；退货类售后等待用户寄回与商家收货。
4. 需要退款时创建统一退款单并调用支付驱动。
5. 回调/查询确认退款成功。
6. 按幂等标识恢复库存、回退资产或佣金并同步订单状态。

### 4.5 插件安装

1. 后台读取插件清单并检查依赖、版本和环境。
2. Installer 在事务外创建扩展表或补充共享表结构。
3. 事务内写菜单、配置、种子、资源归属和安装日志。
4. 启用后，下一请求/进程启动时加载模块路由、事件和处理器。
5. 管理端通过菜单或动态扩展包展示模块页面。

## 5. 权限与数据隔离

- 管理 API 使用管理员 token。
- 非超级管理员通过角色和路由权限校验。
- 后台菜单既是导航数据，也是权限规则的重要来源。
- 客服、门店店员、配送员拥有独立身份校验。
- 对外 API 账号拥有独立令牌类型和接口规则列表。
- 用户端可选认证接口允许游客访问，但资产、订单和个人数据操作必须强制登录。
- 模块路由只有模块已安装并启用时才加载。

## 6. 功能验收建议

对每项上线功能至少验证：

| 维度 | 检查内容 |
|---|---|
