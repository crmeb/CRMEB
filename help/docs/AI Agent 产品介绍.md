# CRMEB AI 助手 · 产品介绍

> 适用范围：对外宣传口径，供产品介绍、方案说明与客户沟通使用。
> 文中的每一项能力都对应系统内已实现的功能，功能事实、接口、数据表与限制以 [AI Agent 模块](AI%20Agent%20模块.md) 为准。

---

## 一句话认识它

**CRMEB AI 助手，是长在管理后台里的运营搭子**——你用一句话提问，它去查系统里真实的订单、商品和用户数据，给出带来源的结论；需要动手改配置、发通知时，它会把「要做什么」摆在你面前，你点确认，它才执行。

它不是嵌在后台的通用聊天窗口，而是一个**读得懂你的商城、动得了你的后台、且每一步都留痕**的智能体。

## 它解决三个具体问题

**1. 「数据在后台，但要翻五六个页面才看得到」**
想知道昨天卖了多少、哪个商品在涨、这批售后卡在哪一步——过去要在订单、商品、售后、优惠券之间来回跳，现在一句话就能问出来。

**2. 「想做周期性报表，只能靠人工每天手动导」**
每日经营日报、每周商品排行、每月用户增长复盘，交给自动化任务，到点自动跑完并把结果发到你的邮箱或企业微信群。

**3. 「想用 AI，但不敢让它碰后台数据」**
AI 助手不会擅自改动数据：涉及写操作的工具一律先弹确认卡等你点头，写权限另有独立密钥，运行过程可完整回放；自动化任务还另有「只读」档位，只能查询与发送通知。放心用，是设计前提而不是事后补丁。

## 核心能力

### 一、会查真实数据的对话

接入系统内 **33 项业务工具**，覆盖商品与分类、订单与物流、售后与退款、优惠券、用户、系统配置、菜单与模块、第三方驱动、邮件与企业微信推送。

回答基于系统实时数据，而不是模型记忆。涉及数字、金额、比率时，助手会**注明数据来源与统计口径**，并清楚区分「工具返回的事实」和「基于事实的分析」。查不到就如实说查不到，不会编造记录。

### 二、能办事，但每一步都请你确认

需要修改数据或对外发送时，助手不会直接执行，而是弹出一张**中文确认卡**：标题写清要做什么，参数逐项列出通俗说明，邮件正文这类富文本内容还会提供**沙箱预览**，你看到的就是将要发出的样子。

确认后按你确认时的参数执行，不会「临时发挥」；点取消则系统不做任何修改。

### 三、会先问清楚，不猜

需要你拿主意、补条件或做选择时（时间范围、统计口径、推广目标），助手会弹出**选择卡**：单选、多选或直接填写，一次只问一个关键问题，问明白了再执行。

即使模型忘了走提问通道、直接在回答里问你，系统也会自动把它转成输入框——**不会出现「AI 在正文里提问、你却不知道往哪答」的情况**。

### 四、越用越贴合你的经营口径

**Skill（技能规则）** 让你把业务约定写成 Markdown 文件交给助手，例如统计口径说明、操作流程、邮件排版规范。系统预置五项，开箱即用：

- **业务助手**：商品、订单、售后、优惠券、用户数据的查询口径与边界说明
- **系统设置**：按配置类型正确构造取值，改前可核对
- **功能说明**：功能归属与配置入口的判断依据，附历史版本速查资料
- **邮件格式**：自动生成美观、邮件客户端兼容的 HTML 正文
- **系统定时任务**：区分系统定时任务与 AI 自动化任务，给出排查边界

未主动指定的技能不会全文占用资源：助手先看到技能目录，判断与问题相关才按需加载。技能规则与助手基础规范冲突时，以你写的技能为准。

### 五、接入你自己的工具

除系统内置工具外，助手支持通过 **MCP 标准协议**接入第三方服务：粘贴一段 Cursor / Claude Desktop 风格的配置即可完成登记，一键同步工具清单、测试连接。

系统已预置 **Tavily 联网搜索** 与 **高德地图** 两项，也可接入你自有的 MCP 服务。工具按服务粒度授权，助手只能调用本次对话挂载的工具。

### 六、无人值守的定时任务

把周期性的事交给它：**每隔若干分钟、每天、每周、每月、每年**五种调度方式。

- 任务指令就是一段自然语言说明，写清口径、时间范围与交付动作即可
- 到点自动执行，结果**推送到邮箱或企业微信群机器人**
- 每次运行都记录状态、耗时、工具调用次数与结果摘要，**可回放全过程**，随时查它到底做了什么
- 支持「只读」与「全自动」两档权限：只读档只能查询数据与发送通知，无法改动业务数据

也可以在对话里直接说「每天早上把昨日经营数据发我邮箱」，助手会把这句话落成一条定时任务，确认后即刻生效。

### 七、模型自由选择

- **一号通 AI 开箱即用**：完成「一号通登录/设置」后即可直接对话，无需再逐条登记模型记录
- **自带模型**：支持 OpenAI 兼容协议，可接入 DeepSeek、通义千问、Kimi、智谱 GLM、豆包、OpenAI，以及 vLLM / Ollama 等自建网关
- 保存前自动做一次**真实连通性测试**，配置有问题当场暴露，不会等到用的时候才失败
- **集中管理**：模型统一在「系统设置 → 模型管理」登记，当前在用哪些模型、哪个是默认一目了然

## 典型场景

| 场景 | 你可以这样说 |
|---|---|
| 经营速览 | 「昨天订单数和销售额是多少？」「最近一周哪个商品卖得最好？」 |
| 售后跟进 | 「今天有哪些新的售后申请？」「这批退款卡在什么状态？」 |
| 用户分析 | 「这周新增了多少用户？有多少人下单了？」 |
| 库存预警 | 「哪些在售商品库存低于 20？」 |
| 配置核对 | 「支付配置现在是什么状态？」「站点地址在哪设置？」 |
| 定时报表 | 「每天早上 9 点把昨日经营数据发到运营邮箱」 |
| 通知触达 | 「给这批用户发一封活动提醒邮件」 |
| 历史功能检索 | 「优惠券的核销记录在哪看？」（附历史版本资料检索） |

## 值得信赖的细节

这些机制不是宣传话术，而是产品为「敢用」做的设计：

- **不把有数据说成没数据**：若工具确实返回了数据、而模型的结论与之矛盾，系统会要求它重新读一遍；仍不一致时，直接向你展示系统确认的工具结果，不让结论跑偏。
- **不编造系统功能**：助手被明确约束——只能基于查证到的模块、菜单与配置给建议。系统没有的页面、配置项不会出现在方案里；查不准的能力会标注「待核实」，而不是编一个出来。
- **时间与口径可追溯**：对话会注入当前系统时间，避免出现照抄示例日期的落款；数字来源与统计区间都会标注。
- **敏感信息不外泄**：工具结果中的密钥、令牌、Webhook 等凭证类字段自动脱敏，手机号也做掩码处理。
- **权限跟随账号**：所有接口走管理后台统一的认证与角色权限，助手能做什么，取决于你账号的权限。
- **全过程留痕**：自动化任务保存完整运行记录，关联会话可回放当时每一步查询与结果。

## 技术特性

- **标准协议**：工具接入采用 MCP（Model Context Protocol）标准，JSON-RPC 2.0 over Streamable HTTP，兼容纯 JSON 与 SSE 两种响应
- **流式体验**：对话与工具执行结果流式推送，思维链与正文分开展示，长任务不空等
- **多轮工具协作**：单次对话支持多轮「查询—分析—再查询」的工具调用，可容纳「问询 + 执行」交替的多步操作
- **可插拔的技能与工具**：技能为文件形态便于版本管理与交接；工具支持系统内置与第三方远程两种来源
- **技能与工具均按需加载**：未用到的能力不占用对话资源

## 启用前提

- AI 助手模块随系统默认安装，后台一级菜单「AI」即为入口
- 内置业务工具依赖 **MCP 服务模块**启用并配置访问密钥；未启用时，仍可使用第三方远程 MCP 工具与对话能力
- 自动化任务依赖系统的队列与定时器进程，以及推送渠道配置（收件邮箱或企业微信机器人 Webhook）
- 模型凭据、邮件与企业微信推送等能力需在后台单独配置与验收
