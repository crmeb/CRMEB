判定顺序：

1. 只是“和第三方说话”，业务规则不变 → 驱动（`driver/`）。
2. 改变商品的库存、履约、售后形态 → product。
3. 改变活动价、购买资格、限购，失败要阻断下单 → trade。
4. 去掉它订单语义不变，只是不再发奖 → marketing。
5. 仍不确定 → 读 [domain-selection.md](../domain-selection.md)，再不确定就问用户。

驱动类别只有上表 10 种。新增驱动类别需要改 `crmeb/` 和 `app/`，超出插件范围，先问用户。

## 2. 停下来问用户的情形

插件必须零侵入：`backend/app/`、`backend/crmeb/`、核心前端、`backend/public/install/`、`composer.json`、`backend/config/`、`.env` 一律不改。下面这些已核实的情形，靠插件目录做不完，必须先向用户说明并取得同意，不要自行修改核心：

| 类型 | 核心里写死的位置 | 后果 |
| --- | --- | --- |
| pay | `eb_pay_channel` 没有新增渠道的接口；`app/services/pay/PayServices.php` 按 `weixin`/`alipay`/`allinpay` 分支；`frontend/uni-app/src/components/payment/index.vue` 按 `channel_key` 的 `switch` 没有 `default` | 只装驱动，后台“支付方式”看不到，端上调不起 |
| logistics | `app/services/shipping/ExpressServices.php` 的 `resolveEnabledQueryDriver()` 只放行 `aliyun_express`、`yihaotong`，`query()` 用 `switch` 解析返回 | 新物流查询驱动启用后抛“物流查询驱动不支持” |
| printer | `app/services/driver/printer/SystemTicketServices.php` 只放行 `YiLianYun`、`FeiEYun`，并按名字拼配置和小票内容 | 新打印驱动无法出票 |
| invoice | 调用方固定 `app()->make(Invoice::class, [yihaotong_config()])`，`Invoice::getDefaultDriver()` 返回 `yihaotong` | 新发票驱动不会被调用 |
| bot | 通知渠道 `DingTalkChannel` 固定调 `Bot::sendMarkdown('ding_talk', ...)`，`EntWechatChannel` 直接发 HTTP，没有飞书或自定义机器人渠道 | 新机器人驱动没有调用方 |
| express | `crmeb\services\logistics\Express` 的命名空间固定为 `\driver\logistics\` | 面单驱动的类必须同时放在 `driver/logistics/{Dir}/`，见分册 |

短信、邮件、上传存储、商品采集按 `driver_key` 动态实例化，新驱动可以零侵入接入（各分册列出了少量仍按 key 写死的分支）。

## 3. 驱动通用机制（所有 01 分册共用）

### 3.1 一条链路

```text
driver/{type}/{Dir}/plugin.json
  → 后台安装：ManifestDriverInstaller（无 Installer.php 时自动使用）
  → BaseModuleInstaller::installDriverRecord() 写一行 eb_driver
  → 运行时 DriverRegistry::scan($type) 只读 eb_driver，并按 owner_plugin_id 过滤未启用插件
  → 业务 Service 取配置 → 门面 new Xxx($driverKey, $config) → Str::studly($driverKey) 拼类名 → 驱动类
```

运行时不扫目录。目录拷进去但没走安装，后台看不到，`scan()` 也拿不到。

### 3.2 必须对齐的四个名字

| 名字 | 规则 | 不对齐的表现 |
| --- | --- | --- |
| 目录名 `{Dir}` | 必须等于 `Str::studly(driver_key)`。例：`ali_pay` → `AliPay`，`aliyun_dm` → `AliyunDm` | 门面抛 `Driver [xxx] not supported.` |
| 命名空间 | `driver\{type}\{Dir}`，类名 `Driver` | 同上；Linux 下 PSR-4 加载失败 |
| `plugin.json` 的 `path` | `driver/{type}/{Dir}`，必须与真实目录完全一致 | 安装报“清单 path 与实际目录不一致” |
| 顶层 `key` 与 `driver.driver_key` | 两者写成同一个值 | 不报错，但复合标识 `driver:{type}:{driver_key}` 与 `key` 不同，排查绕路 |

`Str::studly()` 规则：按 `_`、`-`、空格切分，每段首字母大写后拼接。可以用下面的命令确认：

```bash
cd backend && php -r 'require "vendor/autoload.php"; echo \think\helper\Str::studly("your_key"), PHP_EOL;'
```

反例，不要模仿：`driver/sms/yunxin/`（目录小写，命名空间却是 `Yunxin`，Linux 下会加载失败）；`driver/bot/DingTalk/` 的 `driver_key` 是 `dingtalk`，`Str::studly` 得到 `Dingtalk`，只能靠调用方传 `ding_talk` 才能找到。

### 3.3 plugin.json 顶层

`PluginManifest::fromFile()` 强校验 `key`、`name`、`type`、`version`、`path` 五个非空字符串，驱动还必须有 `driver.driver_key`。

```json
{
    "key": "your_key",
    "name": "显示名",
    "description": "一句话说明",
    "version": "1.0.0",
    "author": "作者",
    "type": "driver",
    "path": "driver/{type}/YourKey",
    "require": { "crmeb": "^8.0", "php": "^8.0" },
    "driver": { "driver_key": "your_key", "name": "显示名" }
}
```

- `version` 固定写 `1.0.0`。项目处于首版开发阶段，规则要求所有插件版本统一 `1.0.0`、不写 `upgrades/` 脚本（见 [架构规范「当前发布阶段」](../../../../rules/架构规范.md)）。用户明确进入发布后维护阶段时才递增版本。
- `default_install`：`true` 表示随系统默认安装。需要用户自备密钥的第三方驱动写 `false` 或不写。

### 3.4 driver 子对象写进 eb_driver 的字段

只有下面这些字段会落库，其他字段只在安装期可读（个别类型的 Service 会回读 `plugin.json`，分册会注明）：

| 字段 | 说明 |
| --- | --- |
| `driver_key` | 必填，`(driver_type, driver_key)` 唯一 |
| `name` | 后台显示名，缺省用顶层 `name` |
| `class_name` | 缺省 `Driver`，不要改 |
| `icon`、`sort` | 展示与排序，`sort` 越大越靠前 |
| `is_builtin` | 见下方启用状态 |
| `capabilities` | 能力声明，数组或对象，按类型约定 |
| `config_fields` | 后台动态表单 |
| `help_doc` | `{"title": "", "steps": [], "link": ""}` |
| `domain_template`、`bucket_fields`、`thumb_watermark_config` | 仅 upload |
| `platforms` | 仅 copyproduct |

安装后的启用状态（`resolveDriverInstallStatus()`）：`is_builtin` 不为真 → 0（关闭）；为真且类型是 `sms`/`email`/`copyproduct`/`logistics` → 同类型已有启用驱动时为 0，否则为 1；其他类型为真 → 1。第三方驱动一律不写 `is_builtin`，装完由管理员在后台启用。

重装用 `ON DUPLICATE KEY UPDATE` 覆盖元数据，不覆盖 `status`。

### 3.5 config_fields 写法

```json
{"field": "your_key_app_id", "label": "AppID", "type": "text", "required": true, "group": "账号", "tip": "说明文字"}
```

- `type` 现役取值：`text`、`password`、`textarea`、`radio`、`select`、`switch`、`upload`。`radio`/`select` 配 `options: [{"value": "", "label": ""}]`。
- 条件显示：`"show_if": {"field": "另一个字段", "value": "取值"}`。
- 默认值：`default`（个别现役驱动写 `value`，新驱动统一用 `default`）。
- 字段名带 `driver_key` 前缀，避免与其他驱动混淆。
- 密钥类字段用 `password`。清单里只写字段定义，绝不写真实密钥。
- 管理员保存的值存在 `eb_driver.config_fields` 每项的 `value` 里（pay 例外，见分册）。

### 3.6 Installer.php

纯驱动不需要写。框架在找不到 `Installer.php` 时自动用 `ManifestDriverInstaller`。只有需要建自有表时才写，写法照 `backend/driver/sms/yunxin/Installer.php`：继承 `crmeb\module\BaseModuleInstaller`，`getKey()` 返回 `driver:{type}:{driver_key}`，`getType()` 返回 `driver`，命名空间与 `Driver.php` 相同。

### 3.7 第三方 SDK

放在 `driver/{type}/{Dir}/extend/` 下，命名空间 `driver\{type}\{Dir}\extend\...`，由根 autoload 的 `driver\` → `driver/` 映射自动加载（参考 `backend/driver/upload/Cos/extend/cos/`）。不改 `composer.json`，不往 `vendor/` 加包。宿主 `vendor/` 已有的包（如 `guzzlehttp/guzzle`）可以直接用。

### 3.8 驱动代码边界

- 驱动只负责和第三方通信：组请求、签名验签、解析返回。
- 不调用 `app\services\*`、不 `use modules\*`、不写业务表。
- 失败时调用 `$this->setError('原因')` 并返回 `false`（`BaseStorage` 子类可用，返回值就是 `false`）。
- 不打印密钥、完整请求签名或用户手机号到日志。

## 4. 模块通用机制（所有 02 分册共用）

### 4.1 启动与路由

- `crmeb\plugin\ModuleRegistry` 扫描 `modules/*/App.php`、`modules/*/*/App.php`、`modules/*/*/*/App.php`。目录下有 `plugin.json` 时，只有插件已安装且启用才调用 `App::register()` / `App::boot()`。
- `App::register(\think\App $app)`：向注册中心登记 Handler、Adapter、定时任务。
- `App::boot(\think\App $app)`：加载本模块 `event.php`（`$app->loadEvent(include __DIR__ . '/event.php')`）。
- 路由文件：`route/admin.php`（挂在 `/adminapi` 下）、`route/user.php`（挂在 `/api` 下），由 `ModuleRouteLoader` 只扫一级和二级目录，未启用模块的路由不加载。
- 控制器放 `controller/admin/`、`controller/user/v1/`，类名以 `Controller` 结尾。
- 命名空间等于目录路径：`modules\{category}\{name}\...`。

### 4.2 plugin.json 的 type

| 落位 | `type` | `key` 现役命名 |
| --- | --- | --- |
| `modules/product/{name}` | `product_type` | `product_{name}` |
| `modules/trade/{name}` | `mode` | `activity_{name}` |
| `modules/marketing/{name}` | `marketing` | 各不相同，新模块建议 `marketing_{name}` |
| `modules/channel/{name}` | `channel` | `channel/{name}` |
| `modules/{name}` | `service` 等 | `{name}` |

`plugin.json` 的 `key`、Installer `getKey()`、菜单、权限、前端扩展 key 必须一致。

### 4.3 脚手架

```bash
cd backend && php think make:module demo --label=演示模块 --type=marketing
```

它只生成扁平目录 `modules/demo/`，命名空间 `modules\demo`，`path` 为 `modules/demo`。要放进 `modules/{category}/` 时，把目录移进去后手工改三处：所有文件的 `namespace`、`plugin.json` 的 `path`、`plugin.json` 和 Installer 的 `type`（脚手架写的 `product`/`trade` 要改成 `product_type`/`mode`）。更省事的做法是复制分册里指定的参考模块。

### 4.4 Installer 要点

继承 `crmeb\module\BaseModuleInstaller`，必须实现 `getKey()`、`getName()`、`getType()`、`runMigrate()`、`rollbackMigrate()`、`getMenuConfig()`。可选覆写 `seed()`、`cleanData()`、`onEnable()`、`onDisable()`（覆写必须调 `parent::`）、`getVersion()`（首版阶段返回 `1.0.0`）。

- 自有表名 `eb_{插件标识}_*`，在 `runMigrate()` 里 `CREATE TABLE IF NOT EXISTS`，在 `rollbackMigrate()` 里删除。不对系统表做 DDL。
- 菜单只通过 `getMenuConfig()` 声明，挂核心父级用 `parent_key`（如 `core:admin-marketing`），同批子菜单用 `'pid' => '@父菜单名'`。可见菜单 `auth_type=1`，接口权限 `auth_type=2` 且必须有 `api_url` + `methods`，按钮 `auth_type=3` + `unique_auth`。完整说明见 [manifest-and-lifecycle.md](../manifest-and-lifecycle.md)「菜单权限」。
- 定时任务：`App::register()` 里 `CrontabTaskRegistry::register($mark, $class)`，Installer `seed()` 幂等写 `system_crontab` 一行（按 `mark` 先查），`cleanData()` 按 `mark` 删。参考 `backend/modules/marketing/signin/Installer.php`。
- 所有写操作幂等，安装、重装、启用、禁用、卸载都能重复执行。

### 4.5 前端

- 管理端插件页面：源码只放 `frontend/admin/src/pages/plugin/<key>/`，见 [admin-extension.md](../admin-extension.md)。不需要独立前端包时，可以用 PHP 声明后台页。
- uni-app 独立页：源码放 `frontend/uni-app/src/pages-modules/<标识>/`。放入后的地址、`routes.js` 跳转、装修链接与验收见 [uniapp-pages.md](../uniapp-pages.md)。Installer 用 `ensurePageLinkCategory()` + `seedPageLinks()` 登记同一条路径；DIY 组件在 `plugin.json` 的 `diy.components` 声明。
- 不改核心前端的类型分支。需要展示扩展字段时，优先走 Handler 返回的 `display_sections`、`page_config` 等数据契约。

## 5. 安装与验证命令

安装没有命令行入口（`app/command/PluginInstall.php` 只是占位）。两种方式：

1. 后台“插件管理”页面安装、启用。
2. 调接口（需要管理员 token，`plugin_key` 可以写复合标识、`path` 或 `key`）：

```bash
curl -X POST 'http://127.0.0.1:8011/adminapi/plugin/install' \
  -H 'Authori-zation: Bearer <admin token>' \
  -d 'plugin_key=driver:sms:your_key'
# 同组还有 plugin/enable、plugin/disable、plugin/uninstall
```

安装、卸载会写数据库，只在用户确认过的开发库或隔离库上执行，不要在不明来源的库上执行。

静态校验（不写库，任何时候都可以跑）：

```bash
cd backend
php -l driver/{type}/{Dir}/Driver.php        # 语法
php think plugin:manifest-check              # 清单、复合身份、Installer 元数据一致性
php think arch:check                         # 依赖方向；当前基线已有 2 处严重违规（modules/service/outapi），只看新增
php think registry:check                     # 模块：产品类型/交易模式/订单适配器/售后规则注册一致性
php think event:check                        # 模块：事件注册一致性（当前基线已有 2 个孤儿事件警告）
```

安装后确认驱动可被发现（只读库）：

```bash
cd backend && php -r 'require "vendor/autoload.php"; (new think\App(getcwd()."/"))->initialize();
$t = "sms"; foreach (crmeb\services\driver\DriverRegistry::scan($t) as $k => $d)
  echo $k, " => ", crmeb\services\driver\DriverRegistry::getDriverClass($t, $k), " status=", $d["status"], PHP_EOL;'
```

期望看到你的 `driver_key` 和 `driver\{type}\{Dir}\Driver`。看不到时按顺序排查：是否已安装 → 插件是否启用 → `owner_plugin_id` 是否非空。

## 6. 交付

- 只交付插件根目录（驱动 `driver/{type}/{Dir}/`，模块 `modules/{category}/{name}/`），以及模块的 `frontend/admin/src/pages/plugin/<key>/`。
- `git diff --name-only` 里不应出现第 2 节列出的核心路径。如果用户同意了核心改动，在交付说明里单独列出。
- 不提交 `.env`、真实密钥、证书、运行时数据。
- 提交信息遵循 [提交规范](../../../../rules/提交规范.md)。
