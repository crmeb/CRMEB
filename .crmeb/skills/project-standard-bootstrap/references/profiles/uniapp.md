# UniApp Profile

## 识别与目录

- UniApp 应用统一位于 `frontend/uni-app/`；多套独立 UniApp 应用使用 `frontend/<应用名>/` 并在项目契约分别登记。
- 从 `package.json` 的 `@dcloudio/*`、Vite 配置、`pages.json` 和 `manifest.json` 判断 CLI 工程、Vue 版本和目标平台。
- 所有 `@dcloudio/*` 依赖保持同一发行版本，升级时整体同步并用 lockfile 固定。
- 先读取 package scripts 获取真实的 H5、小程序和 App 开发/构建命令，不假设项目一定使用 HBuilderX 或某个包管理器。

## 页面与平台边界

- 页面必须登记在 `pages.json` 的主包或分包；控制主包体积并记录分包边界。
- 页面生命周期从 UniApp API 获取，组件生命周期遵循对应 Vue 版本；不要混用导致重复请求或状态丢失。
- 导航、请求、存储、上传、权限和系统能力优先使用 `uni.*` 跨端 API。
- 浏览器 DOM、微信 API、App 原生能力等必须放入正确的条件编译块，块保持成对和平衡。
- 使用 `rpx`、安全区和触屏交互规范；权限、定位、相机、相册等能力同步隐私声明与平台配置。

## 接口与认证

- 追踪“环境变量 → 构建配置 → API base URL → request 封装 → 后端路由”的完整链路。
- 明确 token header、登录过期、刷新/重新登录、语言、租户、设备等公共请求信息。
- API 函数只传领域路径和参数，统一封装响应、错误、超时、取消、上传及未登录处理。
- 前端使用匿名标记前，必须确认后端路由和中间件也允许匿名。
- 后端下发的状态、按钮、页面配置和组件 key 是跨端契约，不能在页面再次硬编码另一套映射。

## 多端验证矩阵

| 改动 | 最低验证 |
| --- | --- |
| 通用页面、组件、API | H5 + 需求指定的至少一个小程序或 App 端 |
| H5 DOM、登录、分享 | 普通浏览器；相关时验证微信内浏览器 |
| 微信/支付宝等小程序能力 | 对应平台开发者工具和真实权限配置 |
| App 原生能力 | 受影响的 Android/iOS 平台，缺少真机时明确限制 |
| `pages.json`、manifest、条件编译 | 所有受影响的平台构建 |

同时覆盖未登录、已登录、token 过期、慢请求、空数据、后端错误、返回页面刷新和重复提交。

## 构建与升级交付

- H5 产物可按部署模型进入核心升级包，并记录 base path、API 地址和缓存刷新方式。
- 微信、支付宝等小程序通常需要重新上传和审核；升级包 manifest 必须提示人工发布步骤，不能声称覆盖已发布小程序。
- App 本地资源包、热更新包、原生安装包和应用商店发布是不同制品，分别记录版本、平台和签名要求。
- `manifest.json`、App ID、证书、平台密钥和生产域名不得用个人或真实秘密模板覆盖。
