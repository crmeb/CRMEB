# 项目文档覆盖矩阵

文档不是固定数量的空文件，而是由项目能力动态生成的可运行知识地图。环境分析器给出 `documentation.required` 和 `missing`，AI 再以源码、配置和实际验证补全内容。

## 所有项目必备

| 文档 | 必须回答 |
| --- | --- |
| `README.md` | 项目用途、组成、五分钟启动、标准命令、文档导航 |
| `help/docs/README.md` | 按角色和任务导航全部正式文档 |
| `project-overview.md` | 用户、边界、主要能力、外部系统和非目标 |
| `architecture.md` | 应用/模块、调用链、进程、数据流、关键决策和扩展点 |
| `development.md` | 版本、依赖安装、配置、初始化、启动和成功信号 |
| `configuration.md` | 变量名、用途、必填性、默认值来源、覆盖顺序和秘密管理 |
| `api.md` | 协议、鉴权、错误、分页、幂等、版本和契约来源 |
| `testing.md` | 静态、单元、集成、端到端、冒烟、测试数据和覆盖边界 |
| `deployment.md` | 构建物、环境、部署步骤、健康检查和回滚入口 |
| `operations.md` | 进程、日志、指标、告警、任务、容量和日常操作 |
| `troubleshooting.md` | 已验证的症状、检查、原因、处理和验证结果 |
| `security.md` | 权限、秘密、敏感数据、依赖风险和安全响应 |
| `upgrade-and-rollback.md` | 版本源、升级路径、迁移、备份、验证、失败恢复 |

## 按能力强制增加

| 检测到的能力 | 必备文档 |
| --- | --- |
| 后端应用 | 后端目录 `README.md` + `help/docs/applications/<后端ID>.md`：职责、入口、分层、任务、异常、事务、命令和调试 |
| 每个独立前端应用 | `frontend/<应用名>/README.md` + `help/docs/applications/<应用ID>.md`：职责、页面/路由、状态、API 客户端、环境、命令、构建和发布 |
| UniApp | `uniapp-development.md`：平台矩阵、条件编译、权限、分包、真机与发布 |
| 数据库 | `database-and-migrations.md`、`backup-and-recovery.md` |
| Docker 本地环境 | `docker-development.md`，并与根 compose/run 逐项一致 |
| worker/queue/scheduler/WebSocket | 在架构、开发和运维文档分别说明启动、健康、日志和重启 |
| 多租户、支付、对象存储、搜索等 | 增加专项边界、数据、安全、故障和测试说明 |
| 可安装升级包 | 升级清单、包格式、校验和、连续迁移与隔离验证 |

## 内容质量门槛

每份正式文档必须链接证据来源，命令写明执行目录、前置条件、成功信号和副作用。待确认内容标注状态和负责人；计划不得写成已实现。禁止真实凭据、生产数据、机器私有绝对路径和无证据版本号。

文档完成不以“文件存在”为标准。至少执行链接检查、事实静态检查和项目标准检查；运行、部署、备份恢复或升级未实际验证时，必须明确验证等级和缺口。

## 逐应用说明文档

每个可独立安装、运行、测试、构建或发布的后端/前端应用都必须有自己的说明，不能用一份笼统的“前端开发”文档代替多个应用。应用目录内的 `README.md` 是开发者就近入口，详细事实文档放在 `help/docs/applications/<应用ID>.md`；两者应以链接分工，避免复制整段内容。

逐应用说明至少由当前代码核对以下事实：

1. 应用用途、用户、边界以及与其他应用的关系；
2. 运行时、框架、包管理器和版本来源文件；
3. 目录入口、路由/页面或请求入口、状态与 API 客户端；
4. 安装、配置、开发、测试、构建、预览和发布命令；
5. 环境变量名称、默认端口、代理、依赖服务和健康信号；
6. 构建产物、部署目标、平台差异以及当前限制；
7. 常见调试入口、日志、测试位置和关联正式文档。

检查顺序是 manifest/lockfile → 构建配置 → 代码入口/路由 → 环境样例 → API 客户端与后端路由 → 测试/CI → 现有说明。旧 README 与代码冲突时按代码和可执行结果更新，不能反过来照抄旧说明。

代码变更影响应用职责、目录、运行时版本、命令、配置、端口、路由、API、权限、数据、构建产物或发布方式时，同一变更必须检查并更新对应应用说明及文档索引。纯内部重构若不改变上述事实，可以不改正文，但交付报告应说明已检查且无需更新。
