# API 与数据库规范

## API 契约

- HTTP/API 风格、版本策略和基础路径在项目中唯一定义。
- 请求校验覆盖类型、长度、格式、枚举、范围和业务权限；未知字段策略明确。
- 成功与错误响应稳定，错误含机器码和可安全展示的信息，不泄露内部异常。
- 列表统一分页、排序和过滤语义；大结果集禁止无边界返回。
- 创建、支付、回调和重试接口定义幂等键或等价机制。
- OpenAPI、GraphQL schema、protobuf 等机器契约是客户端类型和契约测试的优先来源。
- 破坏性变更先提供兼容窗口、弃用说明和升级路径。

## 数据库

- 表、字段、约束和索引遵守项目语言和数据库约定，并在规则中明确。
- 主键、时间、金额、状态、软删除和多租户字段必须有统一类型与语义。
- 索引来自实际查询模式；唯一业务约束优先由数据库保障。
- 迁移只向前追加，已发布迁移不回改；大表采用分阶段兼容迁移。
- UPDATE/DELETE 有精确条件；批量操作评估锁、事务大小和恢复方式。
- 新安装 schema、种子和所有历史迁移必须得到一致结果。

## 契约联动

数据结构变化必须同步检查：Model/Entity、Repository、Service、API schema、前端类型、表单、列表、导入导出、权限、缓存、事件、测试、新安装和升级迁移。

## 验证

- 校验迁移顺序、重复执行行为和失败恢复。
- 对关键查询查看执行计划或等价分析，确认索引命中和结果边界。
- 契约测试覆盖必填/可选字段、错误、分页、权限和版本兼容。
- 禁止把生产数据复制到开发或测试环境，脱敏数据也需遵守授权和保留策略。
