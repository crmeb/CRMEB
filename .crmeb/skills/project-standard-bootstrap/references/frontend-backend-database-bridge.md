# 前端到后端与数据库

本指南帮助以页面开发为主的开发者和 AI 安全完成全栈改动。目标不是要求前端绕过后端直接改库，而是能追踪数据来源、理解影响并使用迁移和测试完成闭环。

## 先建立请求链路

```text
页面/组件
  → 前端 API 函数与类型
  → HTTP 请求封装、认证和 base URL
  → 后端路由与中间件
  → Controller/Handler 输入校验
  → Service/UseCase 业务规则与事务
  → Repository/DAO/ORM
  → 数据库表、索引与迁移
  → 统一响应、错误码和前端状态
```

排查或开发时沿这条链路双向追踪，记录每层真实文件。不要只从页面字段名猜测数据库字段，也不要从表结构直接推断接口权限和业务语义。

## 快速找到后端实现

1. 从前端 API 函数找到请求方法和相对路径。
2. 确认 request 封装添加的 API 前缀、版本、租户和认证头。
3. 在后端路由中搜索静态路径片段；动态参数按路由声明核对。
4. 继续定位 Controller/Handler、输入校验和权限中间件。
5. 从 Service/UseCase 找到业务规则、事务、事件和缓存失效。
6. 从 Repository/DAO/ORM 找到表、字段、关联和查询条件。
7. 从 migration/schema 确认结构真源，不以运行库临时状态代替迁移。

找不到时优先查看路由列表命令、OpenAPI、框架注册器和模块清单，不要新建重复接口。

## 前端常见任务的全链路清单

### 新增一个字段

- 明确字段属于展示、提交、数据库持久化还是计算结果。
- 数据库存储时新增迁移、索引/约束和新安装 schema；设置安全默认值及历史数据策略。
- 更新 Entity/Model、允许字段、Repository、Service 和序列化。
- 更新请求校验、API schema、响应类型、前端类型、表单和展示。
- 覆盖新建、编辑、详情、列表、导入导出和权限场景。
- 将迁移和受影响构建产物加入升级包。

### 新增列表和筛选

- 后端实现分页、排序白名单、筛选校验和权限范围。
- 查询避免 N+1；为实际筛选和排序组合评估索引。
- 响应返回稳定的列表和总数契约。
- 前端在筛选变化时重置分页，防止重复请求并处理空、错和加载结束状态。
- 测试无数据、大数据量、非法筛选、越权和边界页。

### 新增或编辑表单

- 前端校验改善体验，后端校验才是安全边界。
- 后端重新计算价格、权限、所有权和不可由客户端信任的数据。
- 防止重复提交；高风险写操作使用幂等键、版本号或唯一约束。
- 事务覆盖必须同时成功的写入，外部调用失败有补偿策略。

### 权限和菜单

- 前端路由、菜单和按钮控制只负责体验，服务端接口仍必须鉴权和校验对象所有权。
- 权限标识、角色种子、路由中间件和前端指令保持同一稳定 key。
- 新安装数据、存量升级迁移和卸载/回滚边界同步处理。

## 数据库最低知识

- **主键**：稳定标识记录，不把可变化的展示值当主键。
- **唯一约束**：从数据库层阻止重复业务记录，应用仍需返回友好错误。
- **索引**：加速特定查询但增加写入和存储成本，按查询模式设计。
- **事务**：保证一组数据库操作整体成功或失败，不自动覆盖外部网络调用。
- **迁移**：可追踪地改变结构或基础数据；已发布迁移不能回改。
- **外键/软删除**：遵守项目既有策略，删除前确认关联、审计和恢复需求。
- **NULL 与默认值**：区分未知、未填写和空值；不要依赖前端补默认值。

禁止在共享、测试或生产数据库手工改表来代替迁移。需要查看数据时先确认环境和只读范围；SQL UPDATE/DELETE 必须带精确条件并先用 SELECT 验证影响集合。

## 常见错误定位

| 现象 | 优先检查 |
| --- | --- |
| 401 | token 是否发送、是否过期、认证中间件和环境域名 |
| 403 | 角色权限、对象所有权、租户范围；不是简单隐藏按钮 |
| 404 | API 前缀、版本、路由方法、动态参数和代理转发 |
| 422/参数错误 | 前后端字段名、类型、必填、枚举和嵌套结构 |
| 500 | 后端结构化日志、关联 ID、异常链和数据库错误；不要只在前端重试 |
| 列表重复/缺失 | 分页基准、排序稳定性、筛选重置和并发请求覆盖 |
| 保存成功但页面不变 | 响应契约、缓存失效、状态更新和返回页面刷新 |
| 本地可用、容器失败 | base URL、容器服务名、端口、CORS、挂载和环境变量 |

## AI 输出要求

当请求来自主要做前端的开发者时，AI 应：

- 用页面和 API 语言解释后端层级与数据库影响，并给出真实文件定位；
- 明确哪些值由前端提交、后端验证、后端计算和数据库约束；
- 优先修改迁移与代码，不指导手工改库作为正式方案；
- 给出最小可执行验证命令和请求示例，但不暴露真实凭据；
- 说明本次是否涉及权限、缓存、异步任务、历史数据和升级包；
- 不要求用户先掌握后端框架术语才提供可落地方案。
