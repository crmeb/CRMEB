# 全栈开发流程

## 开始前

1. 读取 `.crmeb/AGENTS.md`、相关规则和应用作用域。
2. 用 `.crmeb/project.json` 定位应用、命令和依赖服务。
3. 检查工作区现有改动，确定本任务基线和修改边界。
4. 明确用户角色、权限、业务不变量、验收场景和非目标。

## 变更链路

按实际影响选择，不机械制造无关层：

1. **领域与数据**：业务规则、状态机、表结构、索引、迁移和新安装 schema。
2. **后端**：路由、输入校验、权限、Service、Repository/DAO、事务、事件和任务。
3. **API 契约**：请求、响应、错误码、分页、幂等、版本和 OpenAPI。
4. **前端接口层**：类型、API client、错误映射和兼容处理。
5. **前端体验**：路由、权限、状态、页面、组件、加载/空/错状态和可访问性。
6. **异步与运维**：队列、定时任务、缓存失效、日志、指标和告警。
7. **测试**：领域单测、接口集成、前端组件、关键 E2E 和回归场景。
8. **文档与配置**：环境变量、开发运行、API、部署和运维说明。
9. **升级交付**：迁移、构建产物、manifest、校验和、备份及回滚边界。

## 接口变更同步清单

- 路由和权限注册；
- 请求校验、响应类型、错误码和示例；
- OpenAPI 或其他契约真源；
- 前端 API client、类型和调用方；
- 缓存 key、事件 payload、队列消息和 webhook；
- mock、fixture、契约测试和兼容窗口；
- 发布说明和升级依赖。

删除或重命名字段前先确认所有消费者。跨版本部署时采用先扩展、再迁移、最后收缩的兼容策略。

## 最小验证顺序

1. 针对改动的格式、lint、类型和静态架构检查；
2. 后端领域与接口测试；
3. 前端组件、类型检查和构建；
4. 数据迁移幂等与新安装一致性；
5. Docker 或宿主机 smoke；
6. 关键角色的端到端路径；
7. 升级包静态检查与旧版升级验证。

交付时逐项报告实际执行结果。只通过静态检查不能声明功能、部署或升级已验证。
