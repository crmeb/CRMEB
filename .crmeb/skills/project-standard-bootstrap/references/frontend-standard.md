# 前端通用规范

## 应用与目录

- 每个可独立安装、运行和发布的客户端位于 `frontend/<应用名>/`。
- 共享组件、类型和 SDK 进入显式 workspace package，不通过跨应用相对路径偷渡。
- 页面负责场景编排，业务逻辑进入 composable/hook/service/store；基础组件不依赖具体业务模块。
- API client 统一处理 base URL、鉴权、超时、取消、错误映射和响应解包。
- 前端需求涉及新增字段、筛选、权限、持久化或后端错误时，使用 [前端到后端与数据库](frontend-backend-database-bridge.md) 追踪完整链路，不在页面层猜测或绕过后端。
- 检测到 `@dcloudio/*`、`pages.json` 或 UniApp manifest 时，同时读取 [UniApp Profile](profiles/uniapp.md)。

## 类型与状态

- 接口请求、响应、路由参数、组件属性和事件保持类型安全；避免无理由的 `any` 或类型断言。
- 服务端状态优先由请求缓存层管理；跨页面客户端状态才进入全局 store。
- 派生状态使用计算值，不维护可推导的重复副本；副作用明确生命周期和清理。
- 接口契约变化同步类型、调用方、mock、测试和兼容策略。

## 页面体验

- 页面必须处理 loading、empty、error、无权限、离线/超时和成功反馈。
- 表单有标签、校验、提交中防重复、错误定位和键盘操作。
- 列表有分页或虚拟化策略，搜索与筛选状态可恢复；危险操作二次确认。
- 使用项目设计令牌和共享组件，支持响应式、深色模式及目标浏览器范围。
- 交互元素具备可访问名称、焦点状态和合理对比度；图片和图标提供替代信息。

## 构建与发布

- `.env` 只存本地非入库配置，公开构建变量不得承载秘密。
- lockfile 必须与选定包管理器一致；禁止混用造成依赖解析漂移。
- 构建产物从干净依赖生成并写入升级包或部署制品，不把开发源码冒充线上产物。
- 每个应用独立记录 dev、typecheck、lint、test、build 和 preview/smoke 命令。

## 每个前端应用的说明文档

- 每个 `frontend/<应用名>/` 必须维护就近 `README.md`，并链接到 `help/docs/applications/<应用ID>.md` 的详细说明。
- 不能只维护一份总的“前端开发文档”；管理端、Web、H5、UniApp、小程序、桌面端等独立项目分别核对 manifest、lockfile、构建配置、路由/页面、环境变量、API 客户端、测试和发布脚本。
- 新增或修改命令、端口、代理、路由、权限、API 地址、构建产物、目标平台或发布流程时，同步更新该应用说明和正式文档索引。
- 文档中的版本与命令必须来自当前代码并经过静态或运行验证，不沿用另一个前端项目的配置。
