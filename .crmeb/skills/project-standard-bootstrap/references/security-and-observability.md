# 安全与可观测性

## 安全底线

- 秘钥、令牌、私钥、Cookie、真实账号和生产数据不得入库、日志或升级包。
- 服务端对每个资源执行认证、授权和对象所有权校验，不能依赖前端隐藏按钮。
- SQL 使用参数绑定；上传校验类型、大小、扩展名、存储位置和访问权限。
- 回调、支付和 webhook 验证签名、时间窗、重放与幂等。
- 外部 URL、命令、模板和反序列化输入按风险防 SSRF、注入、路径穿越和代码执行。
- 依赖使用锁文件和可信源，定期扫描漏洞；高风险依赖升级需回归与发布说明。
- 默认最小权限，开发、测试、生产账号和网络隔离。

## 日志与追踪

- 使用结构化日志，统一时间、级别、服务、环境、request/trace/job ID、动作和结果字段。
- 日志写业务标识的安全形式，不记录完整请求体、认证头和敏感个人信息。
- HTTP、队列、定时任务和外部调用传播关联 ID；异常保留可定位根因的内部上下文。
- 定义日志保留、轮转和访问权限，调试日志不得永久开启。

## 指标与健康检查

- 区分 liveness、readiness 和业务 smoke；健康检查不执行高成本写操作。
- 监控请求率、错误率、延迟、资源、数据库、缓存、队列积压和任务失败。
- 为关键业务结果定义指标和告警，告警包含影响、检查入口和处理手册链接。
- 发布与升级标记进入日志/指标，便于关联异常变化。

## 性能与可靠性

- 查询分页、缓存失效、事务时长、超时、重试、熔断和限流有明确策略。
- 重试只用于可重试错误并采用退避与上限；非幂等操作不可盲目重试。
- 外部依赖故障有降级或清晰失败，不无限等待或吞错。
- 性能优化必须有基线和验证数据，不以复杂缓存替代正确性。
