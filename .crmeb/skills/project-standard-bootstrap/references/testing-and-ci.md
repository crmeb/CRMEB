# 测试与 CI 规范

## 测试地图

| 层级 | 目标 | 典型对象 |
| --- | --- | --- |
| 静态检查 | 快速阻止格式、类型、依赖和文档错误 | lint、typecheck、架构、配置、链接 |
| 单元测试 | 验证纯业务规则和边界条件 | domain、service、utility、composable |
| 集成测试 | 验证数据库、缓存、队列和外部适配 | repository、API、migration、adapter |
| 契约测试 | 保证生产者与消费者兼容 | OpenAPI/schema、事件、消息、webhook |
| 端到端/冒烟 | 验证关键用户链路和部署结果 | 登录、核心交易、管理操作、健康检查 |
| 生命周期测试 | 验证安装、升级、回滚和插件启停 | 新安装、旧版升级、失败恢复 |

## 统一门禁

- `check`：格式、lint、类型、架构、文档、配置与密钥扫描。
- `test`：默认可在开发机和 CI 运行的测试集合；慢测试可拆分但需登记。
- `build`：从干净依赖生成所有发布应用和制品。
- CI 必须调用与本地相同的标准命令，不在流水线复制另一套隐藏逻辑。

## 测试要求

- 测试数据可重复创建和清理，不依赖开发者个人数据库状态。
- 外部服务默认使用 fake、sandbox 或受控测试实例；真实写入需明确授权。
- 时间、随机、网络和并发行为可控，失败信息包含场景和关键上下文。
- 修复缺陷时增加能在修复前失败、修复后通过的回归测试。
- 覆盖率只作信号，核心业务不变量和失败路径优先于追求数字。

## CI 顺序

1. 安装锁定依赖并验证 lockfile；
2. 静态 `check`；
3. 单元和集成 `test`；
4. 全量 `build`；
5. Docker/制品 smoke；
6. 迁移和升级包验证；
7. 只有全部门禁通过后才允许发布阶段。

报告缓存命中和跳过原因。缺少秘密或依赖导致的跳过不能写成通过。
