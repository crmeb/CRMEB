# 前端规范（强制红线）

> 边界：本文件承载强制红线与设计验收标准；组件用法、代码现状和适配流程属手册，真源在 `.crmeb/skills/crmeb-admin-ui/SKILL.md`（管理端）与 `.crmeb/skills/crmeb-uniapp-dev/SKILL.md`（移动端）。承接 `.crmeb/AGENTS.md` 硬约束 #4/#5。

## 一、管理端红线（frontend/admin）

1. **主题令牌**：样式只允许使用 `--prev-*` 设计令牌，禁止硬编码主题色/十六进制色值；与 Element Plus 的桥接在 `src/theme/app.scss`。
2. **页面骨架**：页面用卡片分块（搜索卡 + 数据卡）；按钮绑定 `v-db-click`；权限按钮带 `v-auth="['perm-string']"`，路由带 `meta.auth`。
3. **鉴权头拼写**：请求头是 `Authori-zation: Bearer <token>`（后端约定），**禁止"修正"为标准拼写**。
4. **废弃代码勿用**：`src/libs/axios.js` 是废弃遗留，请求一律 `@/libs/request`。
5. **插件路由**：新增 plugin 子目录 `routes.js` 不会被热更新，**必须重启 dev server**。
6. **事件总线**：`@/utils/bus` 的 `off` 必须传与 `on` 相同的具名函数引用。
7. **编辑纪律**：同一文件多处修改必须逐处顺序编辑，禁止同批并行编辑同一文件（会互相覆盖静默丢失改动）。
8. **版权头**：新写文件不添加 CRMEB 版权头。

## 二、移动端红线（frontend/uni-app）

1. **页面路径是跨系统硬契约**：页面目录路径被后端 PHP（订阅消息/支付回跳/菜单过滤）、安装 SQL `eb_page_link`、admin 默认数据（约 97 处）、`pages.json` 四处引用，**禁止随手改名**；确需修改必须四处同步。
2. **契约冻结不可改**：`componentKey` 值、DIY 组件 `defineOptions name` 与模板 `item.name` 比较字符串、easycom 既有标签名、`subpackage/diyComponents/` 文件名（与 `eb_diy` 存量数据对齐）。
3. **路由常量**：所有页面跳转引用 `dynamic-pages/api/routes.js`，禁止硬编码路径。
4. **依赖锁定**：全部 `@dcloudio/*` 锁定同一版本，升级必须整体同步替换。
5. **`src/config/app.js` 勿删**：除接口地址外导出 `HEADER/TOKENNAME/LIMIT/TIMEOUT/EXPIRE`，全项目大量引用。
6. **禁止新增 Vuex 用法、禁止新增 mixin**：状态用 Pinia（`storeToRefs` 解构），复用逻辑用 composables（`useXxx.js`）。
7. **命名**：新 `.vue` 组件 PascalCase，新页面目录 snake_case + `index.vue`；`npm run lint:naming` 只拦新增违规（存量白名单在 `scripts/naming-baseline.json`）。
8. **富文本**：管理端统一 `@/components/wangEditor`，移动端统一 `components/mp-html`，均勿改内部实现。

## 三、接口契约变更同步清单（强制）

**后端接口的路由、出入参字段变更时，必须在同一提交内完成以下全链路同步**（无法同批完成的，在提交信息中显式标注另一端待同步）：

| # | 同步点 | 位置 |
| --- | --- | --- |
| 1 | 后端链路 | `route → Controller → Services → Dao/Model`（方法命名同步见 [代码规范.md](代码规范.md)） |
| 2 | 管理端 API 层 | `frontend/admin/src/api/` 对应函数（url 不含 `/adminapi` 前缀） |
| 3 | 移动端 API 层 | `frontend/uni-app/src/api/` 对应函数 |
| 4 | 菜单与权限 | `eb_system_menus` + 权限规则；**新接口必须登记权限规则，前端隐藏按钮 ≠ 安全** |
| 5 | 安装数据 | 核心变更同步 `backend/public/install/` 对应 SQL；模块自有数据走模块 `Installer`（见 [架构规范.md](架构规范.md) 数据库变更规范） |
| 6 | 移动端页面契约 | 涉及页面路径/按钮 action/展示块时，同步 `dynamic-pages/api/routes.js`、`api/action-map.js` 或 `page_config` 渲染契约 |

## 四、管理端 UI 设计验收标准

### 4.1 适用范围与依据

依据用户提供的 `prev-admin/docs/design-spec.md`（2026-09-15 整理），适用于新建管理端页面及明确要求 UI 整改的区域。存量局部业务修复不要求顺带全量换肤；存量 CSS 数值是现状，不是新页面验收标准。修改文档不代表运行时样式已完成适配。

下表是本仓库采纳后的标准，原文冲突的裁定依据见 [UI 技能](../skills/crmeb-admin-ui/SKILL.md)「设计落地流程」。原图未随文提供，原文的视觉判读、推断和示例业务数据不升级为强制要求；尺寸按文档给出的 CSS px 使用，不再除以 2。若任务有明确的专属设计，记录其适用范围与差异，避免改变无关页面。

### 4.2 基础与页面布局

| 场景 | 验收标准 |
| --- | --- |
| 字体 | 优先苹方，保留系统无衬线回退；主标题 18px/500、副标题 16px/500、次标题 14px/500、菜单 14px/400、正文/控件/提示 12px/400、表头 12px/500；字重为无单位数值 |
| 颜色 | 遵循第一节主题红线；文字语义按本项目 `app.scss` 映射，不照搬参考项目同名变量的色值；深色模式保持文字、背景、边框可辨识 |
| 留白 | 主内容区四周 16px，卡片间距 16px，底部独立操作区距内容卡 16px；卡片内部沿用项目 20px 基准，不能把外边距当作卡片 padding |
| 圆角 | 常规按钮/输入框/下拉/气泡 4px，页面内容卡与模态弹窗 6px，状态标签 2px；圆形按钮与开关按自身高度形成圆角 |
| 页面结构 | 复用现有布局外壳，不在业务页重建导航栏；列表由搜索卡、数据卡与右对齐分页区组成；分组管理可用左树右表，长表单按业务分组；页面标题头的说明文字（pages-header `description`）前置 14px 主色 info 圆形图标（`InfoFilled`），由组件统一渲染，直写结构需自带同款图标 |

### 4.3 按钮、表单与筛选

| 场景 | 验收标准 |
| --- | --- |
| 普通按钮 | 高 32px、12px/400、左右 padding 15px、相邻间距 14px；列表主操作居左；表单提交区主操作位于按钮组最右；文本操作使用 link 形态，不套实体按钮高度 |
| 按钮语义 | 主要操作用 primary，次要操作用默认描边，删除等危险操作保持 danger 语义；禁用/悬停/按下状态通过组件与主题派生，不从图片取色 |
| 表单控件 | 单行控件高 32px；页面编辑控件基准宽 460px，筛选控件基准宽 280px（均指控件，不含 label）；窄容器不超过可用宽度，多行文本、富文本按内容扩展 |
| 标签与说明 | label 在控件左侧右对齐、带中文冒号、距控件 6px；表单 label 预留 7 个汉字，超出折行；单位/后缀在框内右侧，距右 14px，避免与清空/计数图标重叠 |
| 垂直间距 | 输入/下拉/文本项间距 20px，开关/单选/复选项间距 30px，说明文字距控件 10px；校验消息出现时不遮挡下一个字段 |
| 筛选交互 | 搜索、重置固定在搜索卡右上操作区并预留空间，不覆盖字段；完整条件占用不超过 3 行时全显，超过 3 行默认只显示首行并提供展开/收起；按容器实际换行判断，不能把条件个数当行数 |
| 筛选状态 | 展开/收起保留已输入条件；搜索和重置回到第一页，重置恢复默认条件；容器变窄时操作区仍可见、可用且不重叠 |

### 4.4 表格与辅助组件

| 场景 | 验收标准 |
| --- | --- |
| 表头 | 高 48px、12px/500、外沿圆角 4px、背景 `--prev-color-primary-light-9` |
| 表体 | 纯文本行基准 52px，图片/标签/两行文字等复杂行基准 70px，12px/400；长内容可撑高，不截断业务信息；检查整行实际高度，不只设置 `.cell` 高度 |
| 对齐与操作 | 内容、表头和操作按钮左对齐（选择/展开等专用列除外）；操作超过 3 个时保留高频操作，其余进入「更多」，所有动作仍可达并保持权限控制 |
| 图片与标签 | 表格图片 40×40px；常规标签高 24px、小标签高 20px、水平内边距 8px；表格状态不能仅靠颜色表达 |
| 分页 | 复用公共 pagination，数据量由真实 count 驱动，页码与跳转在右侧；不将设计示例的总数或“20 页”写成业务阈值 |
| Tabs | 页面页签 14px、高 54px、选中 500 加粗主色、激活条 3px（全局已定制，页面不重复覆盖字号/高度/激活条，无例外档）；弹窗/抽屉内页签 13px、高 40px（全局已定制）；详情抽屉按弹窗场景处理 |
| 页签与提示区 | Tabs 独立成卡时页签头部不留卡内底部空白（下划线贴卡底）；数据卡顶部提示条（Alert）距页签下划线 10px，提示条至下方动作按钮/表格 14px；提示条与表格同卡，不单独成卡；间距不得用多个类叠加变相放大 |
| 页签与内容同卡 | 状态筛选/内容切换 Tabs 与内容同卡时：字号/高度/激活条走全局定制，页面只处理布局——头部上下零外边距、左右内边距 20px、卡顶部不留白（页签自身垂直居中留白已足够，如售后页、附件管理页），下划线紧贴内容区，内容区上边距自定（常用 15px）；页签横向留白不使用 p-x-* 工具类挂在组件根节点 |
| Tooltip | 内边距上下 5px/左右 8px，宽不超过 400px、高不超过 80px，超出可滚动；长说明优先放可访问的正文或详情容器 |
| 反馈 | 操作结果用自动关闭的 Message，持续说明用 Alert，需用户决定的操作用确认弹窗；加载、空数据、失败与提交中状态完整 |

### 4.5 弹窗与抽屉

| 场景 | 验收标准 |
| --- | --- |
| Dialog | 居中，宽度选 470/540/650/900/1000px：单项、少量字段、中型内容、列表、复杂内容；圆角 6px、标题栏 46px、标题 14px/500、正文 12px/400 |
| Dialog 内部 | 470px 档：标题左距 16px、内容水平 24px/上下 30px、底部留白 20px；540px 档：内容左距 20px、字段间距按表单标准；900px 档：内容左/上距 20px、内容至底部操作/分页 30px、底部留白 20px；其余档位复用公共容器，不从示例补造细节 |
| Dialog 滚动 | 900px 档整体高度不超过 750px；所有档位受视口可用宽高约束，内容超出在 body 滚动，标题、关闭与底部操作可达；footer 按钮组右对齐，取消在前、主按钮在后 |
| 详情 Drawer | 用户/商品/订单等详情从右侧打开，设计宽 1000px、满屏高，窄屏限制在视口内；body 滚动；字段名预留 5 个汉字右对齐、次要色，字段值左对齐、常规正文色；此对齐要求指 KV 字段名，不是抽屉顶部标题 |
| 编辑 Drawer | 按字段密度复用现有表单抽屉；详情的 1000px 标准不强制套到所有编辑抽屉，也不擅改 SchemaDrawer 默认契约 |
| 提交安全 | 编辑容器关闭遮罩点击误关；提交前校验，提交中防重复，失败保留输入，成功按业务刷新；危险操作确认文案说明实际后果 |
