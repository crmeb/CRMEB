# 安全红线（违反即事故）

> 本文件是安全类"法律"，只收一行可判定的强制红线；方案细节、原理与整改指南见 `help/docs/安全与配置.md`（档案馆）。任何一条被违反都必须立即修复。

## 红线清单（强制）

1. **密钥、token、AppSecret、私钥禁止入库**：任何配置文件、脚本、文档中不得出现真实凭据；敏感配置走 `.env`（不入库）或环境变量。⚠️ 现行违规案例：`.mcp.json` 内 tuoluojiang server 的明文 `Authorization: Bearer ...` 且文件被 git 跟踪——整改方式为改为环境变量引用并轮换该 token。
2. **已泄露的密钥必须立即轮换**：从 git 历史删除文件不算修复，历史提交仍可检出；必须先作废旧凭据再签发新凭据。
3. **生产环境 `app_debug` 必须为 false**：调试输出会泄露路径、配置与 SQL；`.env` 中 `APP_DEBUG` 生产必须关闭。
4. **所有鉴权接口必须走框架 token 校验**：管理端 `adminapi`、用户端 `api` 分别使用对应中间件；新增对外接口（`outapi`）必须显式声明鉴权策略，禁止"先上线后补权限"。
5. **前端隐藏 ≠ 安全**：菜单、按钮的 `v-auth` 只是展示层；后端每个写接口必须独立校验权限，禁止只依赖前端隐藏入口。
6. **资源归属校验（防 IDOR）**：用户侧接口操作订单/地址/售后等资源时，必须校验 `uid` 归属；禁止仅凭前端传入的 `id` 直接读写，禁止用自增 id 遍历猜测他人数据。
7. **支付回调三要素**：验签（校验来源签名）+ 幂等（同一订单重复通知不重复发货/入账）+ 金额以服务端计算为准；禁止信任客户端上报的金额、状态。
8. **上传文件不可执行**：上传目录禁止 PHP 执行权限；按白名单校验扩展名与 MIME；校验文件内容，不要信任原始文件名。
9. **SQL 一律走参数绑定与字段白名单**：使用 ORM/`where` 数组与 `field` 白名单；禁止字符串拼接用户输入到 SQL，禁止 `order by`、`limit` 直接接收未白名单化的用户输入。
10. **日志与响应脱敏**：手机号、身份证、银行卡、密码、token 不得明文写入日志或透出到前端/导出文件；异常上报前先脱敏。
11. **插件与依赖供应链**：引入第三方 composer 包/前端依赖前确认来源与维护状态；模块打包分发时 `plugin.json` 声明必须真实，禁止夹带未声明的网络请求或凭据读取。

## 违规处置

- 发现红线违规：先止血（轮换凭据/关闭入口/回滚），再修代码，最后在 PR/提交说明中写明违规项与修复方式。
- 新功能评审时逐条对照本清单；与业务需求冲突时升级讨论，不得静默绕过。
