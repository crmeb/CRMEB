# CRMEB v8 项目代码规范

## 〇、控制器类命名规范

### 0.1 强制要求

**【必须】** 所有控制器的**类名与文件名必须以 `Controller` 结尾**，二者保持一致。该规范适用于 `app/` 与 `modules/` 下的全部控制器。

> 目的：统一命名风格、提升可读性，便于与 Service/Dao/Model 等其它分层快速区分，并支持 IDE 全局检索。

### 0.2 命名规则

| 业务含义 | 类名 / 文件名 | 路由引用 |
|---------|--------------|----------|
| 订单管理 | `OrderController` | `OrderController::class` |
| 商品管理 | `ProductController` | `ProductController::class` |
| 砍价活动 | `StoreBargainController` | `StoreBargainController::class` |
| 小票打印 | `SystemTicketController` | `SystemTicketController::class` |

### 0.3 命名示例

#### ✅ 正确示例

```php
// 文件：modules/trade/bargain/controller/admin/StoreBargainController.php
class StoreBargainController extends AuthController { /* ... */ }

// 路由引用
Route::get('bargain', [\modules\trade\bargain\controller\admin\StoreBargainController::class, 'index']);
```

```php
// 文件：app/adminapi/controller/order/StoreOrderController.php
class StoreOrderController extends AuthController { /* ... */ }

// 路由引用
Route::get('order/list', [\app\adminapi\controller\order\StoreOrderController::class, 'list']);
```

#### ❌ 错误示例

```php
// ❌ 类名/文件名缺少 Controller 后缀
class StoreBargain extends AuthController { /* ... */ }
Route::get('bargain', [\modules\trade\bargain\controller\admin\StoreBargain::class, 'index']);
```

### 0.4 重命名时的同步要求

重命名控制器时，以下三处**必须同步修改**，缺一不可：

1. **文件名**：`StoreBargain.php` → `StoreBargainController.php`（建议用 `git mv` 保留历史）
2. **类声明**：`class StoreBargain` → `class StoreBargainController`
3. **路由引用**：`route/*.php` 中所有 `StoreBargain::class` → `StoreBargainController::class`

> 命名空间不变（控制器仍位于 `controller/admin`、`controller/user` 等目录）。

## 一、控制器方法命名规范

### 1.1 强制要求

**【必须】** 控制器所有方法名必须使用 **小驼峰命名法（camelCase）**。

### 1.2 命名规则

| 方法类型 | 命名示例 | 说明 |
|---------|---------|------|
| 列表页 | `index()` | 获取列表数据 |
| 详情页 | `read($id)` | 获取单个记录 |
| 添加 | `save()` 或 `create()` | 新增数据 |
| 更新 | `update($id)` | 更新数据 |
| 删除 | `delete($id)` | 删除数据 |
| 状态切换 | `setStatus($id)` | 切换状态 |
| 批量操作 | `batch*()` | 如 `batchDelete()` |
| 导出 | `export()` | 导出数据 |

### 1.3 命名示例

#### ✅ 正确示例

```php
class StoreOrderController extends AuthController
{
    public function index() {}        // ✅ 列表
    public function read($id) {}      // ✅ 详情
    public function save() {}         // ✅ 保存
    public function update($id) {}    // ✅ 更新
    public function delete($id) {}    // ✅ 删除
    public function batchDelete() {}  // ✅ 批量删除
    public function export() {}       // ✅ 导出
    public function getList() {}      // ✅ 获取列表
    public function setStatus($id) {} // ✅ 状态切换
}
```

#### ❌ 错误示例

```php
class StoreOrderController extends AuthController
{
    public function get_list() {}     // ❌ 下划线命名
    public function save_data() {}    // ❌ 下划线命名
    public function delete_id($id) {} // ❌ 冗余命名
    public function getInfo() {}      // ✅ 驼峰命名（推荐）
}
```

### 1.4 批量操作与检查

- **批量命名规范化**（snake → camel 批量转换流程）：`crmeb-dev` 技能子文档 `.crmeb/skills/crmeb-dev/references/07-编码规范/apiroute.md`
- **路由与接口映射验证**（控制器类/方法存在性、命名合规）：子智能体 `.crmeb/agents/crmeb-route-validator.md`

## 二、控制器 Services 加载规范

### 2.1 强制要求

**【必须】** 如果控制器构造函数中注入了服务类（Services），则必须在当前类中重新定义对应的属性。

### 2.2 三种支持模式

#### 模式一：单一服务注入（复数形式）

```php
class SystemRouteController extends AuthController
{
    /**
     * @var SystemRouteServices
     */
    protected $services;

    public function __construct(App $app, SystemRouteServices $services)
    {
        parent::__construct($app);
        $this->services = $services;
    }
}
```

#### 模式二：单一服务注入（单数形式）

```php
class ArticleController extends AuthController
{
    /**
     * @var ArticleServices
     */
    protected $service;

    public function __construct(App $app, ArticleServices $service)
    {
        parent::__construct($app);
        $this->service = $service;
    }
}
```

#### 模式三：多服务注入

```php
class RoutineCIController extends AuthController
{
    /**
     * @var NodeEnvironmentServices
     */
    protected $envServices;

    /**
     * @var RoutineCIServices
     */
    protected $ciServices;

    public function __construct(App $app, NodeEnvironmentServices $envServices, RoutineCIServices $ciServices)
    {
        parent::__construct($app);
        $this->envServices = $envServices;
        $this->ciServices = $ciServices;
    }
}
```

### 2.3 属性定义位置

属性定义必须位于：
- **类开始大括号之后**
- **构造函数之前**

### 2.5 排除情况（不需要修改）

以下情况已符合规范，**不需要修改**：

1. **多服务注入且已定义属性**：控制器使用多个服务属性（非 `$services` 命名），且每个属性都已正确定义（如 `$envServices`、`$ciServices`）
2. **无服务注入**：控制器构造函数中没有注入任何服务（仅 `parent::__construct($app)`）
3. **已定义 `$services` 属性**：控制器已定义 `protected $services;` 属性且带 `@var` 注释

## 三、Services 类 DAO 加载规范

### 3.1 强制要求

**【必须】** 业务数据访问一律经 DAO/Model：Controller、Services 中禁止直接调用 `Db::name()` / `Db::table()`（仅 `Installer` 的 `runMigrate()` / `rollbackMigrate()` / `cleanData()` 生命周期方法、迁移脚本与框架生命周期代码例外）；复杂查询经 `DAO::getDb()` 获取模型查询对象。

**【必须】** Services 类继承 `BaseService`（文件名 `BaseService.php`，无 `s`）。

**【必须】** 如果 Services 类中使用了 DAO（数据访问对象），则必须在当前类中重新定义对应的属性。

### 3.2 定义规范

```php
class StoreOrderServices
{
    /**
     * @var StoreOrderDao
     */
    protected $dao;

    public function __construct(StoreOrderDao $dao)
    {
        $this->dao = $dao;
    }

    public function getList($where)
    {
        return $this->dao->getList($where);
    }
}
```

### 3.3 命名约定

| 类型 | 属性名 | 说明 |
|------|--------|------|
| 数据访问对象 | `$dao` | 单数形式 |
| 多个 DAO | `$xxxDao` | 如 `$orderDao`, `$userDao` |

### 3.4 示例

#### ✅ 正确示例

```php
class StoreOrderServices
{
    /**
     * @var StoreOrderDao
     */
    protected $dao;

    /**
     * @var StoreOrderRefundDao
     */
    protected $refundDao;

    public function __construct(StoreOrderDao $dao, StoreOrderRefundDao $refundDao)
    {
        $this->dao = $dao;
        $this->refundDao = $refundDao;
    }
}
```

## 四、路由定义格式规范

### 4.1 强制要求

**【必须】** 路由定义必须使用**数组形式** `[Controller::class, 'method']`，以支持 IDE 的代码跳转和重构功能。

> 当前项目（ThinkPHP 8）全局使用 `[控制器类::class, '方法名']` 数组形式（`backend/app/adminapi/route`、`backend/app/api/route`、`backend/modules/*/route` 均如此），**禁止**使用 `'控制器类@方法名'` 字符串形式（不支持 IDE 跳转/重构）。

### 4.2 定义规范

```php
Route::get('order/list', [\app\adminapi\controller\order\OrderCenterController::class, 'index'])
    ->option(['real_name' => '统一订单列表']);
```

### 4.3 正确与错误示例

#### ✅ 正确示例

```php
// ✅ 使用 [Controller::class, 'method'] 数组形式，支持 IDE 跳转
Route::get('order/list', [\app\adminapi\controller\order\OrderCenterController::class, 'index'])
    ->option(['real_name' => '统一订单列表']);

Route::get('order/detail/:id', [\app\adminapi\controller\order\OrderCenterController::class, 'detail'])
    ->name('OrderCenterDetail')
    ->option(['real_name' => '订单详情']);

Route::put('order/remark/:id', [\app\adminapi\controller\order\OrderCenterController::class, 'remark'])
    ->name('OrderCenterRemark')
    ->option(['real_name' => '订单备注']);
```

#### ❌ 错误示例

```php
// ❌ 字符串形式 '控制器类@方法'，不支持 IDE 跳转与重构
Route::get('order/list', 'app\adminapi\controller\order\OrderCenterController@index')
    ->option(['real_name' => '统一订单列表']);

// ❌ 短路径字符串形式，不推荐
Route::get('order/list', 'order.OrderCenterController/index')
    ->option(['real_name' => '统一订单列表']);
```

### 4.4 优势说明

| 特性 | 数组形式 `[Controller::class, 'method']` | 字符串形式 `'Class@method'` |
|------|----------------------------------------|----------------------------|
| IDE 跳转 | ✅ 支持 Ctrl+Click / Command+Click | ❌ 不支持 |
| 重构支持 | ✅ 自动更新类名/方法名引用 | ❌ 不支持 |
| 代码提示 | ✅ 类名和方法名自动补全 | ❌ 不支持 |
| 类型检查 | ✅ 检测方法是否存在 | ❌ 不支持 |
| 项目现状 | ✅ 全局标准写法 | ❌ 项目无此写法 |

## 五、IDE 支持

### 5.1 快速跳转

- **快捷键**：按住 `Ctrl`（Windows）或 `Command`（Mac）点击方法调用
- **效果**：直接跳转到定义处

### 5.2 自动补全

- 在输入 `$this->services->` 或 `$this->dao->` 时，IDE 自动列出所有可用方法
- 显示方法签名和参数信息

### 5.3 类型检查

- IDE 自动检查方法调用是否正确
- 提供参数类型提示

## 六、检查命令

### 6.1 检查控制器方法命名

```bash
# 查找控制器中使用下划线命名的方法
grep -rE "public function [a-z_]+_" backend/app/adminapi/controller/**/*.php
```

### 6.2 检查控制器 Services 属性定义

```bash
# 查找构造函数中有 services 注入但缺少属性定义的控制器
find backend/app/adminapi/controller -name "*.php" -exec sh -c '
    grep -q "public function __construct" "{}" && \
    grep -q "\$this->services =" "{}" && \
    ! grep -q "protected \$services" "{}" && \
    echo "❌ $(basename "{}")"' \;
```

### 6.3 检查 Services DAO 属性定义

```bash
# 查找 Services 类中使用 DAO 但缺少属性定义的文件
find backend/app/services -name "*.php" -exec sh -c '
    grep -q "\$this->dao =" "{}" && \
    ! grep -q "protected \$dao" "{}" && \
    echo "❌ $(basename "{}")"' \;
```

### 6.4 检查路由定义格式

```bash
# 查找使用字符串形式定义的路由（应无输出；'控制器@方法' 或 '控制器/方法' 均违规）
grep -rEn "Route::(get|post|put|delete|patch)\([^,]+,\s*'" backend/app/adminapi/route backend/app/api/route backend/modules --include="*.php"
```

## 七、总结

| 规范类别 | 核心要求 |
|---------|---------|
| 控制器类命名 | 类名与文件名必须以 `Controller` 结尾 |
| 方法命名 | 必须使用小驼峰命名法 |
| 控制器 Services | 必须在类中定义属性并添加 PHPDoc |
| Services DAO | 必须在类中定义属性并添加 PHPDoc |
| 路由定义 | 必须使用数组形式 `[Controller::class, 'method']`，禁止字符串形式 |
