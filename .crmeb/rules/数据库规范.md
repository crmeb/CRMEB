# 数据库规范

> 真源为 `backend/public/install/crmeb_table.sql`（由数据库实时导出）。本文件只收"新表/改表必须遵守"的强制约定，与现有表结构保持一致；违反即视为不一致缺陷。

## 一、命名与基础约定（强制）

1. **表前缀统一 `eb_`，表名与字段名一律 `snake_case` 全小写**：表名用业务名词（`eb_after_sale`、`eb_order_center`），禁止驼峰、禁止复数后缀堆砌。
2. **主键统一 `id bigint unsigned NOT NULL AUTO_INCREMENT`**，禁止业务字段作主键、禁止复合主键（唯一性用 `UNIQUE KEY`）。
3. **每张表必须有表级中文 `COMMENT`**；**每个字段必须有中文 `COMMENT`**，枚举型字段的 COMMENT 必须列全可选值（如 `状态: pending_audit/audit_passed/...`）。
4. **引擎与字符集固定**：`ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci`，禁止改字符集/排序规则。
5. **禁止外键约束**：表间关联只保留 `xxx_id` 逻辑字段 + 索引，由应用层保证一致性。

## 二、字段类型约定（强制）

| 语义 | 类型 | 说明 |
| --- | --- | --- |
| 主键 / 大表关联 ID | `bigint unsigned` | 关联字段与目标主键类型必须一致 |
| 普通用户/业务 ID | `int NOT NULL DEFAULT '0'` | 非空 + 默认 0，禁止 NULL |
| 时间 | `int NOT NULL DEFAULT '0'` | 10 位时间戳，命名 `add_time` / `*_time`；**禁止 datetime/timestamp** |
| 金额 | `decimal(10,2) NOT NULL DEFAULT '0.00'` | 禁止 float/double 存金额 |
| 布尔 | `tinyint(1) NOT NULL DEFAULT '0'` | 如 `is_del`、`is_show` |
| 枚举/状态码 | `varchar(32) NOT NULL DEFAULT ''` | 存字符串码（如订单中台状态码），**禁止用 magic number** |
| 结构化快照 | `json DEFAULT NULL` | 如商品快照、图片数组；**禁止用逗号拼接字符串存数组** |
| 短文本/单号 | `varchar(n)` | 单号 32/64、名称 128、原因/备注 500、长备注 1000 |
| 长文本 | `text` | 仅在确需超长内容时使用 |

## 三、软删除与数据安全（强制）

6. **业务表一律软删除**：用 `is_del tinyint(1) NOT NULL DEFAULT '0'` 标记，查询默认过滤 `is_del = 0`；**禁止物理 `DELETE`** 业务数据（框架/安装脚本清理除外）。
7. **禁止删除或改名已上线字段/表**：确需废弃时保留字段、在 COMMENT 标注废弃，或走新增字段 + 数据迁移 + 保留旧列一个版本。
8. **新增字段必须带默认值且 `NOT NULL`**（确需 NULL 语义的才允许 `DEFAULT NULL`），避免存量行出现未定义值。
9. **敏感字段禁止明文入库**：密码、支付凭据、token 等按 `安全红线.md` 处理，不得以可逆方式存储。

## 四、索引约定（强制）

10. **命名固定**：唯一索引 `uk_<字段>`、普通索引 `idx_<字段>`、联合索引 `idx_<字段1>_<字段2>`；主键统一 `PRIMARY KEY (id)`。
11. **高频查询条件必须建索引**：`uid`、`order_no`、`*_id`、`status`、`add_time` 等；列表页排序字段也需索引支撑。
12. **联合索引遵循最左前缀**：区分度高的字段放前（如 `idx_type_status (type, status)`）；避免为同一字段建多个冗余单列索引。
13. **索引数量克制**：单表索引不宜超过 6 个，写多读少的表优先合并联合索引；禁止在函数/表达式上建索引用来绕过查询改写。

## 五、变更流程（强制）

14. **任何表结构变更必须同步安装定义与 Model**：`backend/public/install/crmeb_table.sql`（新装；插件自有结构由 Installer 管理）、`Model` 的字段定义/注释；发布后涉及老站时还须同步升级 SQL。是否需要升级逻辑以 [架构规范.md](架构规范.md)「当前发布阶段（强约束）」为准；缺少适用项即视为未完成。
    > 安装 SQL 的**完整同步映射表**（表结构 / 系统配置项 / 配置分组 / 后台菜单 / 字典 / 大表分别对应哪个 SQL 文件，`crmeb.sql.bak` 禁改，模块自有数据不预置核心 SQL）**真源为 `架构规范.md`「数据库变更规范（强约束）」，以该节为准**，本文不重复。
15. **SQL 变更必须可重复执行**：新增字段用 `ADD COLUMN IF NOT EXISTS` 或升级脚本内做存在性判断，避免重复安装报错。
16. **大数据量改表走异步/分步**：为存量表加索引、改类型前评估锁表影响；上千万行表禁止直接 `ALTER` 全表重建，需走分批方案。

## 六、查询写法（强制）

17. **SQL 一律走 ORM/参数绑定与字段白名单**：禁止字符串拼接用户输入；`where`、`field`、`order`、`limit` 必须白名单化（细节见 `安全红线.md` 第 9 条）。
18. **禁止 `SELECT *`**：即使 `BaseDao::selectList()` 的 `field` 默认为 `'*'`，业务调用也必须显式传字段（性能要求见 `性能与缓存规范.md`）。
19. **禁止循环内单条查询/写入**：批量场景用 `whereIn` + 批量查询，或事务内批量 `insertAll`/`saveAll`，避免 N+1。
