# Git 提交规范（单一真源）

> 本文件是提交规范唯一出处。`.crmeb/AGENTS.md` 硬约束 #6 与 `frontend/*/AGENTS.md` 均只引用本文，不复制正文；修改提交约定只改这里。

## 一、提交信息格式（强制）

- **正文用中文**；类型前缀保留英文：`feat` / `fix` / `docs` / `refactor` / `chore` / `style`
- 格式：`type(作用域): 中文描述`

```text
feat(订单中台): 新增售后独立引擎状态推导
fix(商品路由): 修复缺少前导斜杠导致 vue-router 启动抛错
```

## 二、按主题分批提交（强制）

1. 一次 commit 只承载**一个主题**（如启动修复、路由修复、资源路径、纯格式化），禁止大杂烩。
2. 同一文件承载多个主题时用 hunk 拆分（`git add -p` 或 `git apply --cached`）。
3. 重构、纯格式化不得与业务修复混入同一提交。

## 三、禁止提交的内容（强制）

| 类型 | 清单 |
| --- | --- |
| 本地环境 | `.env*`（指向本地/联调后端地址）、uni-app 本地 `manifest.json`、`dist/` 构建产物 |
| 后端本地配置 | **`backend/.env`**（本地数据库/Redis 连接与调试开关）、**`backend/.constant`**（本地常量与密钥配置）——仓库内二者以 **0 字节占位文件**形式跟踪，本地填入真实值后**任何情况下不得 `git add`、不得推送**，即使被 `--force` 或 `-f` 显式指定也不得入库 |
| 密钥凭据 | 任何 token / AppSecret / 私钥 / 证书 / 数据库密码（含 MCP、机器人等工具配置里的 `Authorization` 头）——详见 [安全红线.md](安全红线.md) 第 1 条 |
| 临时产物 | 调试临时脚本、一次性报告、AI 会话产物 |

> 因占位文件已被跟踪，`.gitignore` 对它们**不生效**。本地填值后请执行一次 `git update-index --skip-worktree backend/.env backend/.constant`，使本地修改不再出现在 `git status` 中，从根上避免误提交（`git ls-files -v` 显示 `S` 即已生效）。
>
> 若不慎 `git add` 了真实内容，用 `git restore --staged backend/.env backend/.constant` 撤回，并核对 `git status` 确认无误；凭据已泄露的按 [安全红线.md](安全红线.md) 第 2 条轮换。
>
> 已误提交的密钥必须**立即轮换**——仅删除文件不能使 Git 历史中的旧密钥失效。

## 四、提交前检查（强制）

1. 涉及 `.crmeb/`、各工具软链目录时，核对索引、frontmatter、本地 Markdown 链接及现有入口目标；可选工具目录不要求创建。
2. `git status` 逐文件确认后**按文件名显式 `git add`**，禁用 `git add -A` / `git add .` 盲加（防误提交密钥与临时文件）。
3. 涉及接口契约变更时，逐项核对 [前端规范.md](前端规范.md)「接口契约变更同步清单」。
