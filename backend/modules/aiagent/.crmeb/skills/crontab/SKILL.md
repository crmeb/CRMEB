# 系统定时任务

处理「定时任务在哪 / 有哪些定时任务 / XX 自动取消是怎么实现的 / 定时任务没执行怎么办」等问题时遵循以下规则：

## 一、先区分两类「定时任务」（重点）

用户口中的「定时任务」可能是两种完全不同的东西，回答前先判断归属：

- **系统定时任务**：全局业务自动化，如未支付自动取消订单、订单自动收货、自动好评等，由后台「定时任务」统一管理。涉及商品、订单等系统级自动化行为的提问归此类，按本技能规则处理。
- **AI 自动化任务**：让 AI 助手周期性替用户执行问答任务（如「每天早上把昨日经营数据发我邮箱」），使用 `crmeb_task_create` 创建、`crmeb_task_list` 查询，与系统定时任务无关。

判断不准时不要猜：用一句话向用户说明两种能力的区别，并用 `crmeb_ask_user` 让用户选择指的是哪一种。

## 二、位置类问题（可点击直达）

「定时任务在哪设置」「去哪里加定时任务」「自动取消订单在哪配置」等入口类问题：

- **第一个调用的工具就是 `builtin.crmeb_menu_list`**，用「定时任务」等关键词检索，用返回的 `breadcrumb` 作文字菜单路径、`url`（已含 `/admin` 前缀）作可点击链接，禁止凭记忆自拼路径。
- 具体任务的取消时长、收货天数、好评开关等**业务参数不在定时任务页**，而在系统设置对应分组：先用 `builtin.crmeb_config_list` 按关键词（如「取消」「收货」「自动好评」）定位配置项，再按「告知菜单位置」规则用 `builtin.crmeb_menu_list` 附上该配置分组的入口链接，两边入口都给。

## 三、代码可登记的系统任务（不等于站点实际启用清单）

以下是当前代码中可登记的任务示例，不代表本次站点已登记、开启或正在执行。没有系统任务列表 MCP 工具，问当前实际任务清单时应引导用户查看已查到的后台入口，不以此表代替在线结果：

| 任务名称 | 作用 |
|---------|------|
| 未支付自动取消订单 | 订单超过系统设置的未支付时间后自动取消，释放库存和优惠券 |
| 订单自动收货 | 订单发货后超过系统设置的自动收货天数，自动确认收货并完成订单 |
| 订单商品自动好评 | 订单完成后自动给商品好评 |
| 清除昨日海报 | 自动清除昨日生成的海报图片，释放存储空间 |
| 自动开具发票以及退款自动冲红 | 自动开具电子发票，退款时自动冲红已开发票 |
| 退款一致性恢复 | 查询支付渠道未决退款，并重试渠道成功后的本地产品效果 |
| 微信支付一致性恢复 | 查询支付渠道并恢复相关支付或退款补偿 |
| 未支付订单提醒 | 定时提醒用户支付未支付订单 |
| 会员到期提醒 | 定时提醒即将到期的会员用户 |
| 自定义定时任务 | 执行管理员编写的自定义 PHP 代码 |

规则：

- 已安装模块可能追加自己的系统任务；先用 `builtin.crmeb_module_list` 核对已知模块状态，但模块已安装仍不证明其任务已登记或开启。AI 自动化任务通过对话工具查询，不与系统任务表混为一谈。
- 每个任务在后台列表中独立显示「是否开启」开关、执行周期、上次执行时间、下次执行时间；任务存在 ≠ 已开启，不要把「系统支持」说成「正在自动执行」。
- 具体任务当前的开关状态、执行时间，AI 助手**没有查询工具**，不要编造，如实说明需到后台列表页查看，并附入口链接。

## 四、「任务没执行」排查类问题

用户反馈「自动取消没生效」「定时任务不跑了」时，按以下顺序引导排查，**每一步都只介绍在哪里看、看什么，不代用户下结论**：

1. **任务开关**：确认后台定时任务列表中对应任务的开关已开启（附入口链接）。
2. **驱动方式是否部署**：定时任务依赖两种驱动之一，请用户确认服务器已部署其中一种——
   - URL 驱动：服务器 crontab 每分钟访问一次 `https://你的域名/api/crontab/run`；
   - 命令行驱动：以常驻进程方式运行 `php think timer`（workerman 定时器）。
   AI 无法探测服务器部署状态，禁止替用户断言「已部署/未部署」。
3. **执行周期与上次执行时间**：到列表页查看该任务的「上次执行时间」是否更新、「下次执行时间」是否合理。
4. **业务参数**：确认相关配置值合理（如未支付取消时长、自动收货天数是否被改成超大值），用 `builtin.crmeb_config_list` 查询当前值并按类型展示。
5. **执行日志**：任务执行日志受系统日志开关控制，写入服务器日志文件，AI 无法读取；需要看日志时引导用户到服务器查看，不编造日志内容。

## 五、能力边界与安全

- 内置 MCP 工具清单中**没有**定时任务的查询、启停、保存类工具：AI 不能直接开关任务、修改执行周期或新增系统定时任务，此类诉求一律引导用户到后台操作（附菜单链接），并明确说明「这一步需要你在后台完成」。
- 一次只引导用户处理一个任务，不擅自建议批量开关无关任务。
- 「自定义定时任务」执行任意 PHP 代码，风险高：用户咨询添加自定义任务时，说明其能力与风险，建议优先使用内置任务或联系开发人员；AI 不代写生产环境自定义任务代码后引导直接上线。
- 修改任务的开关、周期等操作由用户在后台完成，AI 不需要也无法二次确认执行结果，如实告知以列表页显示为准。

## 六、常见问答口径

- 「未支付订单多久自动取消？」——先答机制（由「未支付自动取消订单」任务按配置时长自动取消），再用 `builtin.crmeb_config_list` 查当前配置值回答具体时长；查不到配置时告知以系统设置为准并给配置入口。
- 「为什么订单还没自动收货？」——按「任务没执行」排查流程处理，同时核对自动收货天数配置是否尚未到期。
- 「能不能每 5 分钟自动取消？」——执行周期在后台定时任务编辑中配置，引导到后台操作；同时提醒调整周期会影响所有未支付订单，请谨慎评估。
