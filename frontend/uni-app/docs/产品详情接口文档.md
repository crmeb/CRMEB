# 产品详情页接口文档（按产品类型 / 交易类型）

> 面向用户端前端开发，梳理不同产品类型（product_type）与交易类型（activity_type / 活动商品）下，产品详情页相关接口的路径、参数、响应结构与差异。

## 一、接口总览

| 接口 | 方法 | 适用场景 | 说明 |
|------|------|---------|------|
| `/api/product/detail/:id` | GET | 所有产品类型的**统一商品详情**（实物/网盘/卡密） | 扁平结构 + `display_sections` 数据驱动，主详情接口 |
| `/api/seckill/detail/:id` | GET | 秒杀商品详情 | 秒杀活动页 `goods_seckill_details`，可传 `time_id` |
| `/api/combination/detail/:id` | GET | 拼团商品详情 | 拼团活动页 `goods_combination_details` |
| `/api/bargain/detail/:id` | GET | 砍价商品详情 | 砍价活动页 `goods_bargain_details`，可传 `bargainUid` |
| `/api/store_integral/detail/:id` | GET | 积分商城商品详情 | 积分商城页 `integral_goods_details` |

> 前端统一封装见 [api/product-center.js](../api/product-center.js)（统一详情）与 [api/activity.js](../api/activity.js)（各活动详情）。

## 二、统一商品详情接口（核心）

### 2.1 请求

```
GET /api/product/detail/:id
```

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | int | 是 | 中台商品ID（`eb_product_center.id`） |
| `activity_type` | string | 否 | 交易/活动类型，默认 `normal`。取值：`normal` / `integral` / `seckill` / `combination` / `bargain` |
| `activity_id` | int | 否 | 活动商品ID（如拼团活动ID、积分商品ID），`activity_type` 非 `normal` 时使用 |

> 会员专享商品（`vip_product=1`）非会员访问会被拦截；`vip_product=2` 非会员返回 `vip_exclusive=true`。

### 2.2 响应结构（顶层）

```json
{
  "status": 200,
  "msg": "ok",
  "data": {
    "uid": 1,
    "is_money_level": 0,
    "spec_unique": "abc",
    "productAttr": [],
    "productValue": {},
    "storeInfo": {},
    "svip_open": false,
    "svip_price_open": 0,
    "priceName": 0,
    "reply": null,
    "replyChance": 0,
    "replyCount": 0,
    "mer_id": 0,
    "good_list": [],
    "mapKey": "",
    "store_self_mention": 0,
    "activity": [],
    "coupons": [],
    "routine_contact_type": 0,
    "display_sections": []
  }
}
```

| 顶层字段 | 说明 |
|---------|------|
| `storeInfo` | 商品基础信息（扁平，含选择/加购契约），详见 2.3 |
| `productAttr` / `productValue` | 规格数据（实物/网盘多规格；选择型业态由 `display_sections` 承载） |
| `display_sections` | **展示块数组**（各产品类型/交易模式监听器注入，前端按 `order` 升序渲染），详见 3 |
| `reply` / `replyCount` / `replyChance` | 评价数据 |
| `good_list` | 推荐商品 |
| `coupons` / `activity` | 优惠券、活动入口 |

### 2.3 storeInfo 关键字段

| 分类 | 字段 | 说明 |
|------|------|------|
| 标识 | `id` / `product_id` / `product_type` | 商品ID / 中台商品ID / 产品类型（normal/virtual/cardkey） |
| 图片 | `image` / `image_base` / `slider_image` / `attrPics` | 主图（已拼站点URL）/ 轮播图 / 规格图 |
| 基本信息 | `store_name` / `store_info` / `keyword` / `unit_name` / `description` | 名称 / 简介 / 关键词 / 单位 / 图文详情 |
| 价格 | `price` / `vip_price` / `ot_price` / `cost` / `postage` | 现价 / 会员价 / 原价 / 成本 / 运费 |
| 库存销量 | `stock` / `sales` / `fsales` / `ficti` / `browse` | 库存 / 销量（含虚拟销量）/ 虚拟销量 / 浏览量 |
| 状态位 | `is_show` / `is_virtual` / `is_vip` / `is_limit` / `min_qty` 等 | 上下架/虚拟/会员/限购标志位 |
| 预售 | `presale` / `presale_pay_status` / `presale_start_time` / `presale_end_time` | 预售状态（1未开始/2预售中/3已结束） |
| 扩展字段 | `custom_form` / `params_list` / `protection_list` / `label_list` | 由 `ProductDetailExtend` 事件注入（2.4） |
| 用户态 | `userCollect` / `userLike` / `vip_exclusive` | 收藏 / 喜欢 / 会员专享引导 |
| **选择契约** | `selection_spec` | 前端渲染底部选择区的契约（2.5） |
| **加购契约** | `cart_strategy` / `cart_button` | 加购策略与按钮显隐（2.5） |

### 2.4 事件注入的 extensions（写回 storeInfo）

各产品类型监听器通过 `ProductDetailExtend` 事件向 `storeInfo` 注入：

| 字段 | 类型 | 说明 |
|------|------|------|
| `custom_form` | array | 自定义表单配置（下单页用，详情页只读展示数量） |
| `params_list` | array | 参数列表（规格参数键值对） |
| `label_list` | array | 标签完整数据（ID → 数据） |
| `protection_list` | array | 保障服务名称列表 |
| `type_info` | object | 卡片样式/类型标签/单位（`handler->getListExtend()`） |
| `fulfillment_preview` | string | 履约方式说明（如"快递配送 / 到店自提"） |

### 2.5 选择 / 加购契约（前端按此渲染底部栏）

#### selection_spec（选择契约）

| 字段 | 说明 |
|------|------|
| `selection_model` | 选择模型：`matrix`（规格矩阵）/ `temporal`（日期时段）/ `none`（无选择） |
| `confirm_window` | 弹窗模式：`editable`（可编辑）/ `readonly`（只读回显）/ `none`（无弹窗） |
| `required_selections` | 必选维度数组：`sku` / `calendar` / `time_slots` / `price_list` |
| `cart_unit` | 下单计量单位：`item`（件）/ `day`（晚/天） |

#### cart_strategy（加购策略）

| 字段 | 说明 |
|------|------|
| `cart_mode` | `cart`（双按钮：加购+立即购买）/ `direct`（单按钮直接下单） |
| `multi_item` | 是否支持一次购买多个 |
| `button_text` | 按钮文案（空则用默认文案） |

> **cart_button 计算铁律**：`cart_button = (cart_mode === 'direct') ? 0 : 1`。前端无需自行推导，直接消费该字段即可。

## 三、display_sections 数据契约

`display_sections` 是详情页核心扩展机制：后端监听器按商品的产品类型 / 交易类型注入展示块，前端 `pageDesign.vue` 按 `order` 升序渲染。**新增产品类型时前端零改动**。

### 3.1 section 字段

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `key` | string | 是 | section 唯一标识（如 `spec` / `fulfillment` / `store_12`） |
| `component` | string | 是 | 组件类型：`spec_preview` / `info_card` / `store_card` / `time_card` |
| `title` | string | 否 | 区块标题，空则不显示标题栏 |
| `visible` | bool | 是 | 是否可见（后端预算，前端按 `visible !== false` 过滤） |
| `order` | int | 是 | 排序权重（升序），遵守区间约定：产品类型 10-99 / 交易模式 100-199 / 营销 200-299 |
| `data` | object | 是 | 组件数据，结构由 `component` 决定 |

### 3.2 四种 component

| component | 用途 | data 结构 |
|-----------|------|-----------|
| `spec_preview` | 售卖形态展示位（规格/票种/房型等） | `{blocks: [...]}`（6 种 block 组合） |
| `info_card` | 万能信息卡（履约/须知/规则键值对） | `{items: [{label, value, icon?}]}` 或 `{fields: [{label, value}]}` |
| `store_card` | 门店/场馆/酒店地址卡 | `{name, address, lat, lng, phone, store_type, business_hours?, distance?, store_type_label?}` |
| `time_card` | 时间线（预售期/有效期/场次时间） | `{periods: [{label, time, status}]}` |

### 3.3 spec_preview 的 6 种 block 构件

前端 `specPreview.vue` 按 `block.type` 分发到对应子渲染器（`components/productSections/blocks/`）：

| block.type | 名称 | 结构 | 覆盖场景 |
|-----------|------|------|---------|
| `chips` | 属性标签 | `{items:[{label,value}]}` | 卡密面值、卡密类型、当前规格 |
| `matrix` | 规格矩阵 | `{attrs, skus, current_sku?}` | 实物/网盘多规格（选规格看价/图/库存，不采集） |
| `price_list` | 起价列表 | `{items:[{name, price_from, tags?, image?, stock_status?, stock_count?, unique?}]}` | 门票票种、酒店房型 |
| `time_slots` | 时段列表 | `{items:[{name, time, stock_status?, id?}]}` | 门票场次 |
| `calendar` | 日历概览 | `{config:{mode:'single'/'range'}, dates:[{date, status, min_price, stock_level, sku_detail?}]}` | 门票选日期、酒店选入住/离店 |
| `policy` | 政策键值对 | `{items:[{label,value}]}` | 退改政策、限购规则、购买须知 |

`stock_status` 取值：`sufficient`（充足）/ `tight`（紧张）/ `sold_out`（售罄）。各维度一律取"该维度下所有组合中最宽松状态"。

## 四、产品类型维度（product_type 对照）

### 4.1 各产品类型详情输出总览

| 产品类型 | 名称 | spec blocks | 其他 display_sections | extensions 注入 | 兼容交易模式 |
|---------|------|-------------|----------------------|----------------|-------------|
| `normal` | 实物 | `matrix` | `store_card`（支持到店自提且有启用门店时，每门店一个） | 全量 6 字段 | normal/seckill/combination/bargain/integral |
| `virtual` | 网盘 | （暂不输出 display_sections） | — | 全量 6 字段 | normal/seckill |
| `cardkey` | 卡密 | `chips`（卡密类型/有效期/发放方式） | `info_card`（发货：自动发放/无需物流） | 全量 6 字段 | normal |

### 4.2 各产品类型选择/加购契约对照

| 产品类型 | selection_model | confirm_window | required_selections | cart_unit | cart_mode | multi_item | 按钮文案 |
|---------|----------------|----------------|---------------------|-----------|-----------|-----------|---------|
| `normal` | matrix | editable | [sku] | item | cart | true | 默认 |
| `virtual` | matrix | editable | [sku] | item | cart | true | 默认 |
| `cardkey` | none | readonly | [] | item | cart | false | 默认 |

### 4.3 履约能力（影响 info_card 展示）

| 产品类型 | requires_shipping | supports_pickup | isVirtual | fulfillment_preview |
|---------|------------------|-----------------|-----------|---------------------|
| `normal` | true | true | false | 快递配送 / 到店自提 |
| `virtual` | false | false | true | 支付成功后自动发放网盘链接与提取码 |
| `cardkey` | false | false | true | 支付后自动发放卡密 |

## 五、交易类型维度（活动商品）

活动商品详情有**两套接口**：

1. **旧版活动详情接口**（活动专用页面 `goods_seckill_details` / `goods_combination_details` / `goods_bargain_details` / `integral_goods_details` 使用）：返回 `storeInfo` / `productAttr` / `productValue` / `reply` 等旧版扁平结构。
2. **统一详情 + activity_type**（走 `/api/product/detail/:id?activity_type=xx&activity_id=xx`）：由 `ProductDetailExtend` 事件的交易模式监听器**覆盖** storeInfo 的价格/库存/限量并注入额外 `display_sections`。

### 5.1 秒杀 seckill

| 项 | 说明 |
|----|------|
| 接口 | `GET /api/seckill/detail/:id?time_id=xx` |
| 参数 | `time_id`：秒杀时间段ID（必传，决定活动状态与结束时间） |
| 返回 | 旧版扁平结构。`storeInfo.status`：0已结束/1抢购中/2即将开始；`storeInfo.percent`（抢购进度）、`storeInfo.last_time`（活动结束时间戳）、`storeInfo.quota`（限量）、`storeInfo.total` |
| 兼容产品类型 | normal（实物）、virtual（网盘） |

### 5.2 拼团 combination

| 项 | 说明 |
|----|------|
| 接口 | 旧版：`GET /api/combination/detail/:id`；统一：`GET /api/product/detail/:id?activity_type=combination&activity_id=xx` |
| 覆盖字段（统一接口） | `price`（拼团价）、`stock`（拼团库存）、`quota`/`quota_show`（限量）、`unit_name`、`sales`、`title`/`store_name`、`people`（成团人数）、`effective_time`、`start_time`/`stop_time`、`num`（每人限购）、`once_num`（每单限购）、`activity_type`/`activity_id`；`productValue[*]` 逐规格覆盖拼团价/限量 |
| 额外字段 | `storeInfo.pink` / `pinkAll`（进行中的开团列表）、`pink_ok_sum` |
| 额外 display_sections | `combination_info`（拼团信息卡，order=100：拼团价/成团人数/限量）、`combination_quota`（限购规则，order=101：每单限购/每人限购） |
| 兼容产品类型 | normal（实物） |

### 5.3 砍价 bargain

| 项 | 说明 |
|----|------|
| 接口 | `GET /api/bargain/detail/:id?bargainUid=xx` |
| 参数 | `bargainUid`：发起砍价的用户UID（参与砍价场景） |
| 返回 | 旧版扁平结构 |
| 兼容产品类型 | normal（实物） |

> 砍价目前**未实现** `ProductDetailExtend` 监听器，统一详情接口传 `activity_type=bargain` 不会产生活动覆盖，砍价详情请走旧版接口。

### 5.4 积分商城 integral

| 项 | 说明 |
|----|------|
| 接口 | 旧版：`GET /api/store_integral/detail/:id`；统一：`GET /api/product/detail/:id?activity_type=integral&activity_id=xx` |
| 覆盖字段（统一接口） | `price`（兑换积分）、`stock`（可兑换库存）、`quota`（限量）、`unit_name`（积分）、`num`（每人限兑）、`sales`（已兑换）、`title`/`store_name`、`activity_type`/`activity_id`；`productValue[*]` 逐规格覆盖积分价/限量 |
| 额外 display_sections | `integral_info`（兑换说明，order=100：兑换价格/限量/原价）、`integral_quota`（限购规则，order=101：每人限兑） |
| 兼容产品类型 | normal（实物） |

## 七、前端调用示例

```javascript
// 统一商品详情（所有产品类型）
import { getCenterProductDetail } from '@/api/product-center.js';

// 普通商品
const res = await getCenterProductDetail(100);
const { storeInfo, productAttr, productValue, display_sections } = res.data;
// display_sections 按 order 升序渲染（PageDesign 已处理）

// 拼团商品（统一接口，activity_type=combination）
const res2 = await request.get(`product/detail/100`, {
  activity_type: 'combination',
  activity_id: 8,
});
```

```javascript
// 活动专用页面（旧版接口，api/activity.js）
import { getCombinationDetail, getSeckillDetail, getBargainDetail, getIntegralDetail } from '@/api/activity.js';

getCombinationDetail(id);                          // GET /api/combination/detail/:id
getSeckillDetail(id, { time_id });                 // GET /api/seckill/detail/:id?time_id=
getBargainDetail(id, uid);                         // GET /api/bargain/detail/:id?bargainUid=
getIntegralDetail(id);                             // GET /api/store_integral/detail/:id
```

## 八、前端渲染要点与铁律

1. **详情页只读**：详情页仅展示数据，不采集下单数据（数量/表单/地址/日期选择归下单页）。底部栏"立即购买/立即预订"点击后，携带选中的 block 数据（`block_data` 参数）跳转下单页。
2. **display_sections 按 `order` 升序**：前端拿到的数组已排序，但渲染时仍需按 `order` 排序兜底。
3. **`visible` 由后端预算**：前端以 `visible !== false` 过滤即可，**不要做表达式求值**。
4. **block 封闭有限**：6 种 block（chips/matrix/price_list/time_slots/calendar/policy）覆盖所有常见业态，新增产品类型前端零改动。
5. **cart_button 铁律**：由 `cart_mode` 决定（direct=0 / cart=1），前端直接读字段，不要自行按 custom_form/is_virtual/presale 推导。
6. **规格矩阵不采集**：`matrix` block 保留"选规格看价/图/库存"交互，但数据不采集、不下单。
7. **库存为快照**：详情页库存（日历/时段/起价列表）是概览级快照，下单页实时校验；`policy` 中应展示"库存实时变化，以下单为准"。
8. **多语言**：后端下发的 title/label/value 已通过 `lang()` 翻译，前端直接展示，不要二次硬编码。
