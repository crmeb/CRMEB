# 命名规范（文件与目录）

> 适用范围：`frontend/uni-app/src/`。配套检查工具：`npm run lint:naming`（存量违规白名单机制，见 §5）。
> 制定背景：项目存在多代命名风格叠加（旧 CRMEB 页面层 snake_case / 公共组件层 camelCase / v8 新层 PascalCase），本规范以 **「新代码强制、存量冻结」** 为策略收敛命名，避免大规模改名带来的跨系统断裂与上游合并冲突。

## 1. 总则

1. 命名一律使用**英文全拼单词**；禁止中文、拼音（`shuoming.png`、`shan.png`）、无语义缩写（`jf-`、`sgin`）、纯数字序号（`1.png`）。
2. 禁止在同一目录下放置**仅大小写不同**的同名文件（如 `NoticeBar.vue` 与 `noticeBar.vue`）——macOS/Windows 大小写不敏感文件系统下会互相覆盖。
3. **存量冻结**：历史文件不主动批量改名；但新写/新移入的文件必须遵守本规范。改动到某存量文件时，若改名影响面仅在 import 级（可 grep、无跨系统契约），鼓励顺手对齐规范。
4. 本仓库与 gitee 上游（`xazbkj/crmebbz`）保持同步，**禁止对存量文件做与功能无关的大规模重命名**——会显著放大合并冲突。

## 2. 分层规则

| 层 | 规则 | 示例 | 存量处理 |
|---|---|---|---|
| `src/` 顶层目录 | 全小写单词或 kebab-case | `api/`、`dynamic-pages/` | 已合规 |
| `pages/` 页面目录 | **snake_case**，页面入口固定 `index.vue` | `pages/users/user_address/index.vue` | 存量路径冻结（见 §3-1）；新页面必须遵守 |
| `.vue` 组件（`components/`、`dynamic-pages/`、页面内 `components/`） | **PascalCase.vue**；easycom 组件目录与文件同名 | `components/BaseMoney/`、`LogisticsTimeline.vue`、局部组件 `InvoiceModal.vue` | 存量 camelCase（`emptyPage.vue` 等）冻结 |
| `subpackage/diyComponents/` DIY 组件 | **契约冻结层，不适用本规范**；新 DIY 组件文件名必须与数据库 `eb_diy.value` 下发的 `name` 字段一致（camelCase） | `homeComb.vue` ↔ name `homeComb` | 冻结 |
| `composables/` | `useXxx.js`（camelCase） | `useColorTheme.js` | 已合规 |
| `api/` `store/` `utils/` `libs/` `config/` 的 js | **camelCase 或全小写单词**；禁止新增 kebab / snake / PascalCase | `orderCenter.js`、`cache.js` | 存量 `order-center.js`、`points_mall.js`、`new_chat.js` 冻结 |
| static 静态资源（图片等） | **kebab-case 全小写**，带语义前缀（`icon-` / `bg-` / `btn-` / `tab-`），允许数字段 | `icon-cart.png`、`live-01.png` | 存量冻结；新增强制 |

补充说明：

- **easycom**：项目未配置 custom 规则，依赖 autoscan 默认约定 `src/components/组件目录/组件名.vue`，模板标签名即目录名。PascalCase 与 camelCase 标签均已验证可用（`<BaseMoney>`、`<emptyPage>`），新组件统一 PascalCase。
- **页面内局部组件**放在页面目录旁的 `components/` 子目录（复数，勿用单数 `component/`），命名 PascalCase。
- 第三方/移植库目录（`mp-html`、`easy-loadimage`、`zb-code`、verify 验证码树、`*.min.js`）保持原名，不适用本规范。

## 3. 红线：契约冻结清单（改名即断线上功能，禁止触碰）

1. **pages.json 已注册的所有页面 path 与分包 root**。
   页面路径是跨系统硬契约，除本项目内约 300 处硬编码跳转外，以下外部系统写死了这些字符串：
   - backend PHP 约 20 处：订阅消息跳转（`app/jobs/MiniOrderJob.php`、`app/listener/...NoticeListener.php`）、微信发货录入（`crmeb/services/easywechat/orderShipping/BaseOrder.php` 的 `PATH` 常量）、支付回调 returnUrl（`app/services/pay/OrderPayServices.php`）、个人中心菜单过滤（`app/api/controller/v1/PublicController.php`）；
   - `backend/public/install/crmeb_data.sql` 的 `eb_page_link` 表 36 条默认链接（admin DIY 链接选择器数据源）；
   - `frontend/admin/src` 约 97 处默认模板/链接选择器数据（`store/module/moren.js`、`fresh.js`、`goodSelect.js` 等）。
2. **DIY 组件的 `defineOptions({ name })` 与模板中 `item.name == 'xxx'` 比较字符串**——对应数据库 `eb_diy` 存量装修数据的 name 值。改文件名只需同步 `pageDesign.vue` 的 import，但 name 字符串一律不动。
3. **dynamic-pages detail 组件的 `componentKey` 值**——后端 `OrderCenterServices.php` 及各产品模块 listener 下发 `page_config.sections[].component` 的匹配契约。
4. **easycom 既有标签名**（模板中 `<tab-nav>`、`<emptyPage>` 等）——等价于组件路径。
5. **第三方目录**：`components/mp-html/`、`components/easy-loadimage/`、`components/zb-code/`、`pages/*/components/verify/`、`vconsole.min.js`、`static/plugin/`、`static/fonts/`。

## 4. 页面路径改名的正确姿势（仅功能确需时）

页面路径改名必须四处同步，缺一即断：① `pages.json`；② 本项目内全部跳转引用（优先收敛到 `dynamic-pages/api/routes.js` 常量）；③ backend PHP 全部下发点 + `crmeb_data.sql`；④ admin 默认模板数据。历史上已有失配样本：backend 下发的 `/pages/center-order/detail/index`、`/pages/center-product/detail/index` 在 pages.json 中无对应页面。

## 5. 检查工具

```bash
npm run lint:naming          # 全量检查：新增/改名产生的违规（不在白名单）即报错退出
npm run lint:naming:update   # 重建白名单 scripts/naming-baseline.json（PR 中须说明原因）
```

- 工具为零依赖 Node 脚本（`scripts/check-naming.mjs`），规则与 §2 一致，豁免清单内置（§3-5 的第三方目录 + DIY 分包）。
- **白名单机制**：存量违规路径一次性录入 baseline 只放行；之后任何新增违规、或把白名单内文件改名/复制为新违规名，都会被拦下。改名成功的文件在下次 `lint:naming:update` 时自动从白名单清理。
